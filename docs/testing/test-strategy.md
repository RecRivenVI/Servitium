# 测试策略

## 1. 原则

1. **实际运行**：验收必须实际运行测试，不得以代码审查代替。
2. **不跳过**：任何测试被跳过即整体失败。平台或环境限制导致无法运行时，**阻塞并请求用户协助**。
3. **可重复**：连续 3 次完整运行必须全部通过。
4. **隔离**：测试之间不共享可变状态；使用独立临时目录、独立数据库文件与随机端口。
5. **确定性**：不使用固定等待；时间通过 `IClock` 控制；随机使用固定种子。
6. **负向优先**：安全相关能力必须有负向测试，且负向测试的数量不少于正向。
7. **契约驱动**：接口与界面的一致性由契约与自动比对守护，不依赖人工核对。

## 2. 测试层次

| 层 | 分类标记 | 范围 | 依赖 |
| --- | --- | --- | --- |
| 单元 | `Unit` | 纯逻辑：领域规则、状态机、算法、格式化、解析 | 无 I/O |
| 架构 | `Architecture` | 分层依赖、命名、禁止项、契约一致 | 无 |
| 集成 | `Integration` | 真实 SQLite、真实文件系统、真实进程、ConPTY、Job Object、gRPC | 文件系统与进程 |
| 契约 | `Contract` | OpenAPI 与生成客户端一致、protobuf 兼容性、错误码与文档一致、文案完备 | 无 |
| 安全 | `Security` | `security-model.md` 第 14 节的全部 `SEC-*` | 视用例而定 |
| 容量 | `Capacity` | 容量目标下的功能正确性与资源稳定性 | 全链路 |
| UI | `Ui` | WinUI UI Automation | 交互式桌面会话 |
| 端到端 | `EndToEnd` | Playwright + 真实 Server + 真实 Agent + 夹具 + 真实 HMCL | 全部 |
| 需提权 | `RequiresElevation` | 服务安装、ACL、防火墙、MSI | 管理员权限 |

## 4. 覆盖要求

| 范围 | 要求 |
| --- | --- |
| `Servitium.Domain` | 行覆盖 ≥ 85% |
| `Servitium.Application` | 行覆盖 ≥ 85% |
| 整体 | 行覆盖 ≥ 70% |
| 每条需求 | 至少一条测试映射（追溯矩阵） |
| 每个威胁 | 至少一条负向测试 |
| 每个稳定错误码 | 至少被一条测试触发 |
| 每个页面 | 至少一条端到端场景 + 一致性比对 |
| 每种配置格式 | ≥ 10 个真实样本的无损往返测试 |

覆盖率不是唯一质量指标；关键路径必须有针对性测试，即使覆盖率已达标。

## 5. 测试数据

| 类型 | 来源 |
| --- | --- |
| Java 服务端 | `Servitium.JavaServerFixture`（可控行为）；真实 Minecraft 服务端仅用于端到端与用户验收 |
| 配置文件样本 | 真实 Minecraft 服务端与常见插件的配置，含中文注释、混合缩进、特殊转义 |
| 模组样本 | 每种元数据格式各若干真实 JAR（仅取元数据文件，不分发完整模组） |
| 归档样本 | 正常归档 + 构造的恶意归档（ZIP Slip、链接、炸弹、深层嵌套、非法名） |
| HMCL 内容 | 构造的整合内容，含中文目录、中文文件名、含空格文件名、大文件 |
| OIDC | 本地 OIDC 桩 |
| RCON 与 Server List Ping | 协议桩（由 `JavaServerFixture` 提供） |

测试数据放在 `tests/` 下的资源目录，不进入产品构建。

## 6. 测试替身

| 场景 | 替身 |
| --- | --- |
| 单元测试中的端口 | 手写替身或替身库 |
| 集成测试中的 Agent | Agent 桩（用于 Server 侧测试） |
| 集成测试中的控制平面 | 控制平面桩（用于 Agent 侧测试） |
| 时间 | `IClock` 的可控实现 |
| 随机 | 固定种子 |
| 出站 HTTP | 本地 HTTP 服务（不使用外网） |

**端到端测试不使用任何替身。**

## 7. 等待与超时

禁止 `Thread.Sleep` / `Task.Delay` 作为「等到状态就绪」的手段。统一使用轮询助手：

```text
WaitUntil(condition, timeout, pollInterval)
  超时时抛出并附带当时的状态快照（实例状态、日志尾部、进程列表）
```

每个测试有明确超时。默认：单元 5 秒、集成 60 秒、端到端 180 秒、容量按设计时长。

## 8. 失败诊断

失败时保存到 `artifacts/test-results/<运行>/<测试>/`：

* 进程标准输出与错误；
* Server 与 Agent 日志；
* 数据库文件副本；
* Playwright 截图与追踪；
* 终端缓冲快照；
* 失败时刻的实例与节点状态。

## 9. 平台矩阵

下列测试必须在 **Windows 11** 与至少一个 **Windows Server**（2022 或 2025）上各运行一次：

| 测试族 | 理由 |
| --- | --- |
| ConPTY | 版本差异 |
| Job Object 与进程树 | 版本与安全软件差异 |
| Windows 服务宿主与关机 | 服务模型差异 |
| 路径与长路径 | 文件系统配置差异 |
| Java 注册表探测 | 注册表布局差异 |
| 需提权的验收 | 权限模型差异 |

无法获得第二个平台时，按权限阻塞流程请求用户协助。

## 10. 安全测试的特殊要求

* 每个威胁至少一条负向测试；
* 负向测试必须断言「被拒绝」而非「不崩溃」；
* 不得因实现困难而弱化断言；
* 已接受的残余风险（`risk-register.md` 第 7 节）不需要缓解测试，但必须有文档说明的对应测试（例如断言文档中的提示存在于界面上）。

## 11. 性能测试

| 类型 | 说明 |
| --- | --- |
| 微基准 | 不作为门禁；仅用于优化决策 |
| 界面性能 | `PRF-*`，作为门禁 |
| 容量与稳定性 | `CAP-*`，作为门禁 |

性能测试在与开发相同的机器上运行；阈值按 `build-and-validation.md` 第 7 节与 `shared-ui-specification.md` 第 11 节。

## 12. 回归

* 每个被修复的缺陷必须补一条回归测试，编号记入 `docs/records/problem-log.md`；
* 回归测试不得只覆盖「该次触发路径」，应覆盖同类问题的边界。

## 13. 测试的维护

* 测试与实现同阶段编写，不推迟；
* 随机失败视为缺陷，必须定位而非重试；
* 被长期禁用的测试视为缺陷；
* 测试代码与产品代码遵循同一编码规范。
