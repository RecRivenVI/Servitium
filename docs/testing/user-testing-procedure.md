# 用户测试流程

阶段 24 使用本流程。Agent 负责搭建环境、提供材料与支持；用户负责实际操作与判定。

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| 配置 | Development ASP.NET Core、Vite 开发服务器、Debug 构建的 WinUI |
| 数据库 | 独立测试数据库，**不使用**正式数据 |
| 目录 | 独立测试目录，**不指向**用户的真实实例 |
| 日志 | 可见且路径已告知 |
| 进程 | PID 已告知，可识别可终止 |
| 网络 | 默认仅回环 |
| 清理 | 测试结束后销毁环境并删除测试数据 |

启动与停止：

```powershell
./eng/StartAcceptanceEnvironment.ps1
./eng/StartAcceptanceEnvironment.ps1 -Stop
```

## 2. 预置数据

| 类型 | 内容 |
| --- | --- |
| 用户 | Owner、Administrator、User（仅授权 2 个实例） |
| 节点 | 2 个（可为同机运行的两个 Agent 实例，使用不同数据目录） |
| Java 运行时 | 至少 2 个（1 个探测、1 个导入） |
| 实例 | 6 个：运行中 2、已停止 3、已崩溃 1；其中 1 个为「附加已有目录」创建 |
| 计划任务 | 至少 3 个（三种触发方式各一） |
| HMCL | 1 个 Channel，2 个 Release（第二个相对第一个有新增、修改、删除三类变化） |
| 文件与配置 | `server.properties`（含中文注释）、`bukkit.yml`、若干模组 JAR、若干测试文件 |

## 4. 反馈方式

用户对每一项给出：通过 / 不通过 / 有疑问。不通过时提供：

* 操作步骤；
* 实际结果；
* 期望结果；
* 截图（可选）；
* 时间点（便于查日志）。

Agent 把每条反馈记入 `docs/records/problem-log.md`，标注严重度并给出处置。

## 5. 判定

| 严重度 | 定义 | 处置 |
| --- | --- | --- |
| 阻断 | 核心流程不可用、数据丢失、安全问题 | 必须本轮修复并回归 |
| 高 | 主要功能明显缺陷 | 必须本轮修复并回归 |
| 中 | 次要功能缺陷或体验问题 | 与用户确认本轮修复或记为已知限制 |
| 低 | 文案、细节 | 同上 |

## 6. 完成

* 全部阻断与高严重度问题已修复并回归；
* 中低严重度问题已与用户确认处置；
* 修复后 `eng/Validate.ps1 -Profile FrontendGate` 全量通过；
* **用户明确确认验收通过**；
* 环境已销毁，测试数据已清理，无残留进程。

用户确认后，Agent 更新 `docs/records/current-status.md` 与 `docs/testing/acceptance-matrix.md`，并**等待用户明确启动交付**。
