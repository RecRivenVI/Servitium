# 需求追溯矩阵

本文件是**可持续更新**的动态记录，由后续编码 Agent 在实现与测试过程中维护。

它只记录事实与映射关系，**不能用于绕过受保护规格**。需求本身的变更走 `docs/records/change-requests.md` 流程。

## 1. 使用方式

每条需求一行：

| 列 | 说明 |
| --- | --- |
| 需求 | `docs/product/functional-specification.md` 中的编号 |
| 阶段 | 实现该需求的开发阶段 |
| 实现位置 | 主要的类型、模块或文件（相对仓库根） |
| 测试 | 覆盖该需求的测试编号（可多条） |
| 状态 | `未开始` / `进行中` / `已实现未测试` / `已通过` / `阻塞` |
| 备注 | 阻塞说明、关联问题编号 |

**文档一致性检查会断言**：

* `functional-specification.md` 中定义的每条需求在本文件中都有一行（可以是「未开始」，但不能缺行）；
* 本文件中不存在未在 `functional-specification.md` 中定义的需求编号。

状态只描述本行当前证据：`进行中` 表示生产代码与列出的自动测试族已有证据，但对应阶段 Gate、真实样本、平台矩阵或用户验收尚未全部完成；`已实现未测试` 明确表示代码存在但该需求规定的正式验证尚未运行。任何一行都不会因为共享测试族通过而自动提升为阶段通过。
