# MCSManager 行为链矩阵

证据快照：`MCSM@072fc59`，现有条目的验证方式均为 `[SOURCE]`。版本复核与决定变更规则见 `source-evidence-index.md` 和 `AGENTS.md`。

本文件按业务场景记录 MCSManager 的完整行为链，格式统一为：

```text
用户动作 → 前端校验 → API 请求 → 控制平面行为 → 节点行为 → 状态变化 → 实时事件 → 前端反馈 → 失败与恢复
```

每个场景末尾给出 **Servitium 采用决定**，说明 Servitium 保留哪一部分行为、改变哪一部分、以及为什么。编号 `BM-###` 供 `docs/design/` 与 `docs/testing/` 引用。

## 0. 通用机制

在阅读各场景前，先明确三条贯穿全局的机制。

### 0.1 控制平面到节点的调用模型

`[SOURCE]` `panel/src/app/service/remote_command.ts`、`remote_service.ts`、`daemon/src/service/router.ts`

面板持有到每个节点的 Socket.IO 客户端连接（面板是客户端，节点是服务端）。所有面板→节点调用都是「发一个命名事件 + 等待同 UUID 的响应事件」的请求-响应模式，超时后抛错。节点侧用一个轻量路由器把事件名分发到处理函数，并在其上叠加鉴权中间件。

**Servitium 采用决定**：连接方向**反转**——Agent 主动连接控制平面（`REQ-NOD-010`）。理由：Windows 节点常位于 NAT 或防火墙之后，让 Agent 出站连接可免去入站端口暴露与端口映射；同时消除「面板保存节点明文密钥」这一凭据模型。调用模型改为 gRPC 双向流上的显式定义方法，不保留通用事件转发（对应排除 MCSM-134）。

### 0.2 权限中间件

`[SOURCE]` `panel/src/app/middleware/permission.ts`（由各路由以 `permission({level, token, speedLimit})` 引用）

每个端点声明最低角色。`ROLE.USER` 级端点在业务层再调用 `isHaveInstance(user, daemonId, instanceUuid)` 做实例级校验；`ROLE.ADMIN` 级端点直接放行管理员。存在 `speedLimit` 与 `token`（CSRF）两个可关闭的开关。

**Servitium 采用决定**：采用「端点声明角色 + 业务层实例级校验」的两级模型（`REQ-IDN-030`），但**不允许**任何端点关闭 CSRF 校验；授权判定统一收敛到单一授权服务，REST、SignalR、文件流与 Agent 指令四条路径共用（`REQ-IDN-031`）。

### 0.3 长操作模型

`[SOURCE]` `daemon/src/service/async_task_service/`

MCSManager 的长操作（实例更新、安装）通过 `asynchronous` / `stop_asynchronous` / `query_asynchronous` 三个事件管理，任务状态存在节点内存中，面板轮询查询。

**Servitium 采用决定**：统一为 `OperationId` 长操作模型（`REQ-PLT-020`）——所有可能超过 5 秒的动作立即返回 `202` 与 `OperationId`，进度通过 `/hubs/v1/events` 推送，状态可通过 `/api/v1/operations/{id}` 查询，支持取消。任务状态持久化到 SQLite，控制平面重启后仍可查询终态。

## BM-001 节点注册

### MCSManager 行为链

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 节点页点击「新增」，填写显示名、IP、端口、密钥、路径前缀 |
| 前端校验 | 显示名必填；IP 必填并提示是否需要地址映射；端口必填；新增时密钥必填（编辑时留空表示不变） |
| API 请求 | `POST /service/remote_service` |
| 控制平面行为 | 生成节点 UUID，把 `{ip, port, apiKey, prefix, remarks}` 持久化，立即尝试建立 Socket.IO 连接 |
| 节点行为 | 节点在 `auth` 事件中校验 `apiKey` 与配置文件中的 `key` 是否相等；相等则标记该连接为已认证 |
| 状态变化 | 节点 `available` 由 false 变 true；节点上报系统信息与实例列表 |
| 实时事件 | 面板缓存节点状态，前端轮询 `GET /service/remote_services` 刷新 |
| 前端反馈 | 节点卡片显示为在线，展示平台、版本、实例数、CPU、内存 |
| 失败与恢复 | 密钥错误或不可达时 `available` 保持 false，卡片以危险色显示；提供「重连」按钮触发 `GET /service/link_remote_service`；节点版本与面板期望版本不一致时以危险色标注版本号 |

### Servitium 采用决定

**适配**。Servitium 的注册流程：

1. 管理员在控制平面生成**一次性注册令牌**（含有效期、可选的预期节点名），控制平面展示令牌与控制平面地址；
2. 在目标 Windows 机器上安装 Agent-only 安装包，安装时或安装后通过配置向导填入控制平面地址与注册令牌；
3. Agent 主动发起 TLS 连接并出示注册令牌；控制平面校验后**签发长期节点凭据**（只存哈希），令牌立即作废；
4. Agent 持久化凭据，后续重连使用凭据而非令牌；
5. 控制平面记录节点的协议版本，握手时做版本协商，不兼容时拒绝连接并在节点页明示原因；
6. 支持凭据轮换与吊销；吊销后节点立即断开且无法重连。

保留：显示名、备注、在线状态、平台信息、实例统计、版本一致性提示、远程地址映射（`REQ-NOD-030`）。
去掉：面板保存明文密钥、节点监听端口、面板 IP 白名单。
新增：注册令牌、凭据轮换、协议版本协商、心跳与最后在线时间。

对应需求：`REQ-NOD-010` … `REQ-NOD-042`。

## BM-002 实例创建

### MCSManager 行为链

MCSManager 有三条创建路径：新建空实例、上传压缩包、附加已有目录（另有从市场安装，Servitium 排除）。

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 快速开始向导选择应用类型与创建方式；填写名称、节点、启动命令、停止命令、工作目录 |
| 前端校验 | 名称必填；节点必选；停止命令必填；上传方式下必须先完成上传；提交前弹出「最终确认」对话框 |
| API 请求 | `POST /instance/`（新建/附加）或 `POST /instance/upload`（上传） |
| 控制平面行为 | 校验管理员权限；把创建请求转发到目标节点；成功后记录操作日志 |
| 节点行为 | 生成实例 UUID；若 `cwd` 为空则在 `defaultInstancePath` 下按 UUID 创建目录；写入实例配置；注册生命周期任务；若为上传方式则解压归档到工作目录 |
| 状态变化 | 实例进入 `STATUS_STOP` |
| 实时事件 | 无推送，前端主动刷新列表 |
| 前端反馈 | 跳转到实例列表或直接进入该实例控制台 |
| 失败与恢复 | 目录不可写、名称非法、节点离线均返回错误消息；上传失败时前端显示进度条错误；已创建但解压失败的实例会残留 |

### Servitium 采用决定

**采用**三条路径并强化：

* **新建空实例**：控制平面校验 → Agent 在登记的基路径下创建目录 → 标记 `OwnedByServitium = true`；
* **上传归档创建**：分片上传到 Agent 暂存区 → 归档安全检查（ZIP Slip、炸弹、符号链接、大小与条目数上限）→ 解包 → 标记 `OwnedByServitium = true`；
* **附加已有目录**：管理员填写任意绝对路径 → Agent 校验路径存在、可读写、不是系统目录、不是其他实例的工作目录或其子目录 → 标记 `OwnedByServitium = false`。

`OwnedByServitium` 标记决定删除时是否允许递归删除目录（见 BM-011）。

创建流程是长操作（`OperationId`），失败时 Agent 必须回滚已创建的目录（仅当 `OwnedByServitium = true`）。

对应需求：`REQ-INS-010` … `REQ-INS-012`、`REQ-FIL-072`。

## BM-003 实例启动与停止

### MCSManager 行为链（启动）

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 实例卡片或控制台点击「启动」 |
| 前端校验 | 仅在 `STATUS_STOP` 时显示该按钮；Minecraft Java 类型先调用 EULA 检查，未同意时弹窗要求确认 |
| API 请求 | `ALL /protected_instance/open?uuid=&daemonId=` |
| 控制平面行为 | 校验角色与实例授权；转发到节点；记录操作日志 |
| 节点行为 | 状态置 `STATUS_STARTING`；按 `processType` 选择进程启动器；解析启动命令；应用 `ie`/`oe` 编码与 PTY 设置；启动子进程；注册退出监听 |
| 状态变化 | `STOP → STARTING → RUNNING`；`lastDatetime` 更新 |
| 实时事件 | 进程输出通过已建立的 stream 通道推送给所有观察者 |
| 前端反馈 | 状态标签变为运行中（绿色）；按钮组切换为停止/重启/终止 |
| 失败与恢复 | 启动失败（可执行文件不存在、目录不可访问）时状态回到 `STOP` 并把错误写入输出流；`eventTask.autoRestart` 开启时按 `autoRestartMaxTimes` 自动重启 |

### MCSManager 行为链（停止）

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 点击「停止」，弹出确认对话框 |
| API 请求 | `ALL /protected_instance/stop` |
| 节点行为 | 状态置 `STATUS_STOPPING`；向进程标准输入写入 `stopCommand`（`^C` 表示发送中断）；等待 `stopTimeout` 秒；超时后强制终止 |
| 状态变化 | `RUNNING → STOPPING → STOP` |
| 失败与恢复 | 超时后走终止路径；进程树中的孙进程可能残留 |

### Servitium 采用决定

**采用**并强化：

* 状态机固定为 `Stopped → Starting → Running → Stopping → Stopped`，另加 `Busy`（长操作占用）、`Crashed`（非预期退出）、`Unreachable`（节点离线）（`REQ-INS-040`）；
* 启动前的 EULA 检查保留（`REQ-INS-064`）；
* **进程树控制强化**：每个实例的进程置于独立的 Windows Job Object，配置为 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，保证强制终止时整棵进程树被回收，Agent 崩溃时也不留孤儿进程（`REQ-TRM-003`）；
* 停止序列固定为：写入停止命令 → 等待 `StopTimeoutSeconds` → 发送 CTRL+BREAK → 再等 5 秒 → 关闭 Job Object（`REQ-INS-041`）；
* 崩溃识别：进程退出码非 0 且不是由 Servitium 主动停止触发 → `Crashed`，触发自动重启策略并记录（`REQ-INS-066`）；
* Windows 关机时按 `enableSoftShutdown` 等价配置优雅停止全部实例（`REQ-INS-070`、`REQ-INS-071`）。

对应需求：`REQ-INS-040` … `REQ-INS-043`、`REQ-INS-062` … `REQ-INS-071`、`REQ-TRM-003`。

## BM-004 终端会话

### MCSManager 行为链

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 进入实例控制台页 |
| 前端校验 | 需要该实例的访问权限 |
| API 请求 | `POST /protected_instance/stream_channel?daemonId=&uuid=` |
| 控制平面行为 | 生成一次性口令；调用节点 `passport/register` 注册该口令与目标实例；把 `{password, addr, prefix, remoteMappings}` 返回给浏览器 |
| 节点行为 | 保存口令与关联实例 |
| 前端后续 | 浏览器**直接**用返回的地址（经 `remoteMappings` 转换）建立到节点的 Socket.IO 连接，发送 `stream/auth` 携带口令 |
| 节点行为（续） | 校验口令；标记该 socket 为已认证；把该实例的输出流转发给这个 socket；socket 断开时停止转发 |
| 状态变化 | 实例 `watcher` 计数增加 |
| 实时事件 | 输出以 256 字符块、每 50 ms 刷新的节奏推送；`stream/input` 与 `stream/write` 反向传入；`stream/resize` 调整 PTY 尺寸 |
| 前端反馈 | xterm.js 渲染输出；支持 ANSI 颜色（按 `haveColor`）；显示观察者人数 |
| 失败与恢复 | 口令无效返回错误并断开；网络断开后前端自动重连并重新走 `stream_channel` → `stream/auth` 流程；实例继续运行不受影响 |

### Servitium 采用决定

**适配（架构级改变）**。Servitium 的浏览器与桌面客户端**不直连节点**：

* 客户端连接控制平面的 `/hubs/v1/terminal`（SignalR）；
* 控制平面按会话与实例授权校验后，在与 Agent 的 gRPC 双向流上打开一条终端子流；
* 输出从 Agent → 控制平面 → 所有订阅该实例的客户端；输入反向。

理由：

1. 消除「浏览器需要能直连每个节点」的网络前提，与「Agent 主动出站」的决策一致；
2. 授权判定只在控制平面发生一次，不需要在节点侧维护第二套口令体系；
3. 权限变更可即时生效——控制平面撤销授权时立即关闭对应客户端的终端订阅（`REQ-IDN-032`）。

保留：多客户端同时观察、观察者计数、PTY 开关与初始尺寸、`resize`、ANSI 颜色、输入输出编码、换行模式、输出历史缓冲、断线重连、实例在控制平面离线时继续运行。

新增：终端会话日志导出（`REQ-TRM-033`）、快捷命令面板（`REQ-TRM-011`）。

`remoteMappings` 在 Servitium 中保留但语义改变：用于**节点自报的对外可达地址**，供文档、诊断与玩家连接信息展示，不再用于浏览器直连（`REQ-NOD-030`）。

对应需求：`REQ-TRM-001` … `REQ-TRM-033`。

## BM-005 文件上传

### MCSManager 行为链

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 文件管理页选择「上传文件」或「上传文件夹」 |
| 前端校验 | 弹出「确认上传」对话框；检查当前目录可写 |
| API 请求 | 先 `GET /files/status` 获取任务配额，再 `ALL /files/upload`（multipart） |
| 控制平面行为 | 按 `speedLimit(3)` 限速中间件与实例授权校验；把上传流转发到节点 |
| 节点行为 | 校验目标路径未逃逸出实例工作目录；受 `maxFileTask` 并发限制；受节点 `uploadSpeedRate` 限速；写入目标文件 |
| 状态变化 | `globalEnv.fileTaskCount` 增减 |
| 实时事件 | 前端通过 XHR 进度事件展示百分比 |
| 前端反馈 | 顶部进度条 + 暂停/继续按钮；完成后刷新列表 |
| 失败与恢复 | 超出并发上限时拒绝；磁盘写失败返回错误；**不支持断点续传**，中断后需整体重传 |

### Servitium 采用决定

**适配**。Servitium 采用分片上传：

1. `POST /api/v1/instances/{id}/files/uploads` 创建上传会话，返回 `UploadId`、分片大小与已收分片位图；
2. `PUT /api/v1/instances/{id}/files/uploads/{uploadId}/parts/{index}` 上传单个分片，携带分片校验和；
3. `POST …/uploads/{uploadId}/complete` 合并，Agent 侧以临时文件累积并在完成时原子替换目标；
4. `DELETE …/uploads/{uploadId}` 取消并清理暂存。

会话可跨连接恢复，客户端重连后先查询已收分片位图再续传（`REQ-FIL-020`）。

保留：并发上限、速率限制、目录穿越校验、进度展示、暂停/继续。
新增：断点续传、分片校验、磁盘空间预检（上传前检查目标卷剩余空间是否足够，不足时直接拒绝并给出所需与可用容量）（`REQ-FIL-064`）。

对应需求：`REQ-FIL-020` … `REQ-FIL-022`、`REQ-FIL-060` … `REQ-FIL-064`。

## BM-006 文件下载与 URL 下载

### MCSManager 行为链（下载）

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 文件行的「下载」动作 |
| API 请求 | `ALL /files/download` |
| 控制平面行为 | 校验授权；向节点申请一次性下载口令；把浏览器重定向到节点地址 |
| 节点行为 | 校验口令与路径；按 `downloadSpeedRate` 限速输出文件流 |
| 失败与恢复 | 口令过期、路径非法返回错误；无 `Range` 支持，中断需重下 |

### MCSManager 行为链（URL 下载）

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 点击「从 URL 下载」，输入 URL 与目标文件名 |
| API 请求 | `POST /files/download_from_url` |
| 节点行为 | 受 `maxDownloadFromUrlFileCount` 并发限制；发起出站 HTTP 请求；边下边写入目标文件；进度写入任务表 |
| 实时事件 | 前端轮询 `GET /files/status` 展示进度条 |
| 用户动作（取消） | `POST /files/download_from_url_stop` |
| 失败与恢复 | 出站失败、磁盘满、并发超限均返回错误；**无 SSRF 防护** |

### Servitium 采用决定

**采用并强化**：

* 下载统一经控制平面流式中转（不重定向到节点），支持 `Range` 与 `206`，支持断点续传（`REQ-FIL-030`）；
* URL 下载保留并发上限、进度、取消；
* **新增 SSRF 防护**（`REQ-SEC-030`）：仅允许 `http`/`https`；解析后的每一跳 IP 都必须不属于回环、链路本地、私有网段、保留网段与节点自身地址（除非管理员在系统设置中显式加入私有源白名单）；逐跳重定向重新校验，防 DNS rebinding；超时与最大重定向次数固定；下载大小上限可配置。

对应需求：`REQ-FIL-030` … `REQ-FIL-033`、`REQ-SEC-030`。

## BM-007 文件编辑

### MCSManager 行为链

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 文件行的「编辑」动作，或从配置总览进入 |
| 前端校验 | 按扩展名判断是否为文本；超大文件给出提示 |
| API 请求 | 通过节点 `file/edit` 事件读取内容 |
| 节点行为 | 按实例 `fileCode` 解码文件内容 |
| 前端反馈 | Monaco 编辑器展示；`Ctrl+S` 保存 |
| 保存 | 再次调用 `file/edit` 带内容参数，节点按 `fileCode` 编码后**直接覆盖**目标文件 |
| 失败与恢复 | 编码不匹配会产生乱码；覆盖过程中断会损坏文件；无备份 |

### Servitium 采用决定

**采用并强化**：

* 保留 Monaco 编辑器、编码选择、快捷键保存；

## BM-011 实例删除

### MCSManager 行为链

| 阶段 | 行为 |
| --- | --- |
| 用户动作 | 实例卡片或列表的「删除」/「永久删除」动作 |
| 前端校验 | 弹出对话框，含一个「同时删除文件」复选框；勾选后按钮变为危险色；批量删除时展示将被删除的目录路径 |
| API 请求 | `DELETE /instance/?daemonId=`，请求体 `{uuids: [], deleteFile: bool}` |
| 控制平面行为 | 校验管理员权限；转发到节点；记录操作日志 |
| 节点行为 | 停止实例；注销生命周期任务与计划任务；删除实例配置；若 `deleteFile` 为真则**递归删除工作目录** |
| 状态变化 | 实例从列表消失 |
| 失败与恢复 | 目录被占用时删除失败，实例登记已被移除但目录残留 |

### Servitium 采用决定

**适配（安全强化）**。这是不可协商的决策之一。

Servitium 把删除拆成两个独立操作：

1. **删除登记**（`REQ-INS-014`）：移除实例记录、计划任务与授权，**永不触碰文件系统**。任何实例都可执行。
2. **删除工作目录**（`REQ-INS-015`）：**仅当** `OwnedByServitium = true`（即该目录由 Servitium 在受管基路径下创建）时才可用。执行前：
   * 实例必须处于 `Stopped`；
   * 二次确认对话框要求用户键入实例名称；
   * Agent 再次校验该目录仍在受管基路径之下、不是基路径本身、不含重解析点；
   * 删除采用逐条枚举而非直接递归删除 API，遇到重解析点即中止并报错。

对于 `OwnedByServitium = false` 的外部工作目录，界面上**不提供**删除目录的入口，并在删除登记的对话框中明确说明「目录 `<路径>` 将被保留」。

理由：附加外部目录的用户很可能指向了包含其他重要数据的路径；一次误操作的递归删除不可逆。

对应需求：`REQ-INS-014`、`REQ-INS-015`。
