# MCSManager 前端布局与交互证据

证据快照：`MCSM@072fc59`，验证方式为 `[SOURCE]`。本文档逐页记录该快照下的界面结构，并给出 Servitium 的适配决定。

Servitium 的最终页面规格由 `docs/design/information-architecture.md` 与 `docs/design/shared-ui-specification.md` 定义。新版功能分布、布局或交互需要复核时，按 `source-evidence-index.md` 取证；界面契约变化按 `AGENTS.md` 处理。

MCSManager 的 Ant Design Vue 控件、颜色、图标、样式与文案一律不复用。可参考的是信息架构、功能入口组织、页面区块关系、操作流程、状态反馈与多节点工作流。

## 1. 全局壳层

`[SOURCE]` `frontend/src/views/LayoutContainer.vue`、`frontend/src/components/**`

| 区域 | MCSManager 事实 | Servitium 适配 |
| --- | --- | --- |
| 外壳 | 单一 `LayoutContainer` 承载几乎所有路由；路由只决定加载哪一组卡片 | 保留「路由 → 卡片集合」的思路用于仪表盘页，但功能页改为常规组件页，不走布局引擎 |
| 侧栏位置 | 全局主题项 `sidebarPosition ∈ {left, right}`；`right` 实为「只保留顶栏」 | 保留两种形态：`左侧导航` 与 `仅顶栏`；Desktop 固定使用 NavigationView，Web 两者皆可 |
| 主导航项 | 由路由 `meta.mainMenu` 决定：`/`、`/instances`、`/market`、`/overview`、`/users`、`/node`、`/settings`、`/customer`、`/login`、`/_open_page`、`/shop` | 见 `docs/design/information-architecture.md` 第 2 节 |
| 面包屑 | 启动时由路由树预计算并写入 `meta.breadcrumbs`，含名称、路径、权限 | 保留面包屑，改为运行时从路由定义派生 |
| 页面标题区 | 通用组件 `BetweenMenus`：`#left` 标题、`#center` 搜索、`#right` 主操作 | 保留三分区页头模式（标题 / 过滤 / 主操作），以 Fluent 2 实现 |
| 卡片容器 | 通用组件 `CardPanel`：`#title`、`#operator`、`#body` 三插槽 | 保留三区卡片模式 |
| 窄屏判定 | `useScreen()` 提供 `isPhone`；多处以 `v-if="!isPhone"` 隐藏标题、把按钮组收进下拉菜单、把表格换成卡片 | 采用同一策略：窄屏隐藏页面标题、动作收进溢出菜单、表格转卡片列表 |
| 加载态 | 全局 `Loading` 组件 | 采用骨架屏 + 进度指示 |
| 空态 | 全局 `Empty` 组件，带描述与可选主操作按钮 | 采用：图标 + 一句说明 + 一个主操作 |
| 错误反馈 | `reportErrorMsg()` 统一弹出消息；`notification.success()` 用于成功 | 采用：非阻塞提示条 + 详情可展开 |
| 危险确认 | `Modal.confirm({okType: "danger"})`，部分场景在正文中列出将受影响的路径 | 采用，并对不可逆操作强制键入名称确认 |
| 设计模式 | 全局状态 `containerState.isDesignMode`，开启后卡片可拖拽编辑，且所有实例操作按钮被禁用 | 采用，仅作用于仪表盘页 |
