# 交付计划

本文件**只定义未来流程，不执行交付**。

**开发完成不自动进入交付。** 交付是用户验收之后的独立任务，必须由用户另行明确启动。

## 1. 交付范围

| 产物 | 内容 |
| --- | --- |
| 完整安装包 | `Servitium.Server` + `Servitium.Agent` + `Servitium.Desktop` + Web 构建产物 |
| 远程 Agent 专用安装包 | 仅 `Servitium.Agent` |
| 发布说明 | 版本、变更、已知限制、升级注意事项 |
| 校验值 | 每个产物的 SHA-256 |

**不提供** Portable 形态（`DEC-07`）。

## 2. 启动条件

下列条件**全部**满足时，交付才可以启动：

| # | 条件 | 判定依据 |
| --- | --- | --- |
| 1 | 后端完整验收通过 | `docs/testing/acceptance-matrix.md` 第 2 节全部通过；阶段 18 门禁状态为通过 |
| 2 | Web 与 Desktop 的 Agent 自测通过 | `acceptance-matrix.md` 第 3 节全部通过；阶段 23 完成 |
| 3 | 用户在测试环境完成测试 | `acceptance-matrix.md` 第 4 节全部完成 |
| 4 | 用户明确确认验收通过 | 用户的明确表述，记录日期 |
| 5 | **用户随后明确要求开始交付** | 用户的明确表述 |

第 5 条是独立的。用户确认验收通过**不等于**授权开始交付。

## 3. 交付流程

### 3.1 交付前门禁

| # | 检查项 | 判定 |
| --- | --- | --- |
| D-01 | `eng/Validate.ps1 -Profile Delivery` 全量运行（**含需要提升权限的阶段 22 与 MSI 场景**） | 退出码 0，所有必需检查均已执行 |
| D-02 | 连续 3 次完整运行 | 无随机失败 |
| D-03 | 依赖漏洞扫描 | 无高危项 |
| D-04 | 许可合规检查 | 全部依赖为宽松许可（见 `engineering-standards.md` 第 2 节） |
| D-05 | 版本号已确定并写入构建配置 | 见 3.2 |
| D-06 | 发布说明已撰写 | 见 3.6 |
| D-07 | `docs/records/problem-log.md` 无未关闭的阻断与高严重度问题 | |
| D-08 | 受保护文档无未经批准的修改 | 文档一致性检查 |

### 3.2 版本号

| 项 | 规范 |
| --- | --- |
| 格式 | `<主>.<次>.<修订>[-<预发布>]` |
| 首个正式版本 | 由用户在交付启动时确定 |
| 传播 | 程序集版本、文件版本、`InformationalVersion`、Web 的构建常量、MSI `ProductVersion` |
| MSI 升级 | `ProductVersion` 的前三段决定升级检测；`UpgradeCode` 在产品生命周期内不变 |

### 3.3 Release 构建

```powershell
./eng/Build.ps1 -Configuration Release -Version <版本号>
```

要求：确定性构建；启用源链接；产物输出到 `artifacts/`。

### 3.4 完整 MSI

`installer/Servitium.Setup/`，WiX 项目。

| 项 | 规范 |
| --- | --- |
| 安装内容 | Server、Agent、Desktop、Web 构建产物 |
| 默认安装目录 | `%ProgramFiles%\Servitium` |
| 默认数据目录 | `%ProgramData%\Servitium`，安装时可指定 |
| 组件选择 | 可选择是否安装 Desktop；Server 与 Agent 至少选其一 |
| Windows 服务 | 安装 `Servitium.Server` 与 `Servitium.Agent` 服务，设为自动启动 |
| 服务账户 | 默认使用专用的本地服务账户；可指定已有账户 |
| 服务恢复策略 | 第一次失败重启、第二次失败重启、后续失败重启；重置计数 1 天 |
| 数据目录 ACL | `SYSTEM` 与 `Administrators` 完全控制；服务账户完全控制；`Users` 无权限 |
| 防火墙规则 | **可选项，默认关闭**；勾选后为控制平面监听端口创建入站规则 |
| 前置条件 | .NET 运行时（自包含则无需）、Windows App SDK 运行时、WebView2 Runtime |
| 界面语言 | `zh-Hans` 与 `en-US` |
| 首次运行 | 安装完成后可选择打开浏览器进入初始化 |

### 3.5 Agent-only MSI

`installer/Servitium.Setup.Agent/`。

| 项 | 规范 |
| --- | --- |
| 安装内容 | 仅 `Servitium.Agent` |
| 默认安装目录 | `%ProgramFiles%\Servitium Agent` |
| 默认数据目录 | `%ProgramData%\Servitium\Agent` |
| 配置 | 安装界面中填写控制平面地址与注册令牌（也可安装后配置） |
| 服务 | 安装 `Servitium.Agent` 服务，自动启动，同样的恢复策略 |
| 防火墙 | **不需要**入站规则（Agent 主动出站） |
| `UpgradeCode` | 与完整安装包不同 |

### 3.6 TLS 与反向代理

安装器不代为配置 TLS。发布说明中给出两条路径：

| 路径 | 说明 |
| --- | --- |
| 直接 TLS | 在系统设置中配置证书来源（Windows 证书存储按指纹，或 PFX 文件 + 密码） |
| 可信反向代理 | 在系统设置中启用可信代理模式并配置可信网段与代理头；由前置代理终止 TLS |

默认部署仅监听回环，无需上述配置（`DEC-16`）。

### 3.7 安装验证（在干净系统上）

| # | 场景 | 检查 |
| --- | --- | --- |
| I-01 | 干净安装（完整包） | 服务已安装并运行；数据目录已创建且 ACL 正确；Web 可访问；初始化流程可用 |
| I-02 | 干净安装（Agent-only 包） | 服务已安装并运行；可用注册令牌接入控制平面 |
| I-03 | 升级安装 | 数据保留；数据库迁移成功；服务继续运行；旧版本文件被替换 |
| I-04 | 修复安装 | 文件被还原；数据未受影响 |
| I-05 | 卸载（保留数据） | 服务被移除；程序文件被删除；数据目录保留 |
| I-06 | 卸载（删除数据） | 需二次确认；数据目录被删除 |
| I-07 | 服务恢复 | 强杀服务进程后自动重启 |
| I-08 | 未安装前置条件 | 给出明确提示而非静默失败 |
| I-09 | 非管理员运行安装 | 触发权限提升；拒绝时给出明确说明 |
| I-10 | 安装后重启系统 | 服务自动启动；实例按自动启动配置恢复 |

上述验证**需要管理员权限与干净系统**。若当前环境不具备，按 `docs/development/development-workflow.md` 第 7 节的权限阻塞流程请求用户协助，**不得跳过或以静态审查代替**。

### 3.8 数据保留与删除

| 场景 | 行为 |
| --- | --- |
| 升级 | 数据目录、数据库、内容库、实例工作目录全部保留 |
| 卸载（默认） | 保留数据目录；提示其路径 |
| 卸载（勾选删除数据） | 删除 Servitium 数据目录（数据库、内容库、归档、备份、日志）；**不删除**位于受管基路径之外的实例工作目录，并在卸载完成页列出这些路径 |
| 任何情况 | 绝不递归删除 `OwnedByServitium = false` 的外部工作目录（`DEC-12`） |

### 3.9 代码签名

| 项 | 规范 |
| --- | --- |
| 默认 | 产出**未签名**的测试产物；发布说明中明确标注并说明 SmartScreen 可能告警 |
| 签名 | 需要用户提供证书与明确授权；签名操作**不由 Agent 自行完成** |
| 签名对象 | 可执行文件、DLL、MSI |
| 时间戳 | 使用 RFC 3161 时间戳服务器 |

### 3.10 发布说明

内容：

* 版本号与发布日期；
* 产品简介与目标平台；
* 本版本包含的能力（按功能域）；
* 已知限制（含 `risk-register.md` 第 7 节的已接受残余风险，用面向用户的表述）；
* 安装与升级说明；
* 默认仅监听回环、如何安全地开放访问；
* 数据目录位置与备份建议；
* 校验值（SHA-256）；
* 产物是否签名。

### 3.11 校验值与产物清单

```powershell
Get-FileHash artifacts/installers/*.msi -Algorithm SHA256
```

清单写入发布说明并随产物一同发布。

### 3.12 Git 标签

| 项 | 规范 |
| --- | --- |
| 格式 | `v<版本号>` |
| 时机 | 交付产物通过全部验证之后 |
| 授权 | **需要用户明确授权**；未经授权不得打标签 |
| 签名 | 若用户提供签名密钥则签名标签 |

### 3.13 GitHub Release

| 项 | 规范 |
| --- | --- |
| 授权 | **需要用户明确授权**；未经授权不得创建 Release |
| 内容 | 发布说明正文 + 两个 MSI + 校验值文件 |
| 预发布标记 | 版本号含预发布段时勾选 |

## 4. 可选任务（默认关闭）

> 在用户于交付阶段明确选择后，编写用于发布 GitHub Release 的 GitHub Actions 工作流。

该任务默认关闭。在用户明确选择之前：

* **不得创建** `.github/workflows/`；
* 不得编写任何 CI 配置；
* `eng/Validate.ps1` 是唯一的验证手段。

用户选择启用时，工作流的范围为：在打标签时构建 Release 产物、运行 `eng/Validate.ps1`、生成校验值、创建 GitHub Release 草稿。是否自动发布由用户决定。

## 5. 交付后

| 项 | 说明 |
| --- | --- |
| 记录 | 在 `docs/records/development-log.md` 中记录交付日期、版本、产物与校验值 |
| 状态 | 更新 `docs/records/current-status.md` |
| 问题 | 交付后发现的问题记入 `docs/records/problem-log.md` |
| 下一轮 | 后续版本重新走开发 → 验收 → 交付流程 |

## 6. 明确不做的事

| 不做 | 理由 |
| --- | --- |
| 开发完成后自动进入交付 | 交付是独立任务，需用户明确启动 |
| 未经授权打标签、推送或发布 | Git 规则（见 `AGENTS.md`） |
| 自行进行代码签名 | 需要用户提供证书与授权 |
| 在用户选择前创建 CI 工作流 | 本文件第 4 节 |
| 跳过干净系统的安装验证 | 需要时请求用户协助 |
| 卸载时删除外部工作目录 | `DEC-12` |
