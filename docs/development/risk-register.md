# 风险登记

本文件登记 Servitium 开发中已识别的风险、影响、应对与触发信号。风险状态的实时变化记录在 `docs/records/problem-log.md`；本文件是基线，不随进度更新。

严重度：`高` = 可能导致产品无法交付或存在安全事故；`中` = 可能导致返工或功能受限；`低` = 局部影响。

## 1. 技术风险

### RSK-001 ConPTY 行为差异（高）

**风险**：ConPTY 在不同 Windows 版本上的输出编码、尺寸调整与关闭时机存在差异；Java 服务端在伪终端下的输出可能与重定向管道不同。

**影响**：终端乱码、尺寸不生效、进程退出后残留读取线程。

**应对**：
* 阶段 14 在 Windows 11 与 Windows Server 2022/2025 上各跑一次终端集成测试；
* 提供按实例关闭伪终端的开关，回退到重定向管道（`REQ-TRM-002`）；
* 输出解码使用实例配置的编码，而不是依赖控制台代码页；
* 集成测试用 `JavaServerFixture` 输出 ANSI、非 ASCII 与超长行。

**触发信号**：终端出现乱码、尺寸调整无效、进程退出后 CPU 占用不降。

### RSK-002 Job Object 与进程树回收（高）

**风险**：Java 服务端可能派生 breakaway 的子进程；某些安全软件会干预 Job Object。

**影响**：强制终止后残留进程；Agent 崩溃后遗留失控的 Java 进程。

**应对**：
* 显式禁止 breakaway（`JOB_OBJECT_LIMIT_BREAKAWAY_OK = false`）；
* 设置 `KILL_ON_JOB_CLOSE`；
* 集成测试 `SEC-230`、`SEC-231` 强制覆盖；
* 测试夹具支持派生多层子进程。

**触发信号**：测试中出现残留的 `java.exe`。

### RSK-003 配置文件无损往返（高）

**风险**：`properties`、YAML、TOML 的保留结构解析器实现复杂，边界情况多（续行、锚点、多行字符串、注释位置、数值精度）。

**影响**：玩家的配置注释与顺序丢失，属于不可逆的数据损失；`REQ-CFG-020` 无法通过。

**应对**：
* 阶段 15 优先实现并用大量真实样本做往返测试（每种格式至少 10 个样本，含中文注释与混合缩进）；
* 无法保证无损的格式先降级为「仅原始文本编辑」并明确标注，而不是提供会丢失内容的结构化编辑；
* 写入前备份（`REQ-CFG-021`）作为兜底；
* 若某格式的成熟保留结构解析库不可用，走变更请求评估自实现成本。

**触发信号**：往返测试出现字节差异。

### RSK-004 SQLite 并发（中）

**风险**：64 个实例 + 20 个会话 + 8 个终端下的写入竞争。

**影响**：写超时、请求延迟升高。

**应对**：WAL、单写入队列、读连接池、`busy_timeout`；容量测试断言 P95 延迟；指标采样批量写入而非逐条。

**触发信号**：容量测试中出现 `SQLITE_BUSY` 或延迟超标。

### RSK-005 WebView2 在 Desktop 中的可靠性（中）

**风险**：WebView2 Runtime 缺失、版本差异、初始化失败、内存占用。

**影响**：Desktop 的终端与编辑器不可用。

**应对**：
* 启动时检测 Runtime，缺失时给出明确指引而不是崩溃；
* 终端与编辑器为独立的 WebView2 实例，失败时降级为「只读文本视图」并提示改用 Web 界面；
* 安装器把 WebView2 Runtime 列为前置条件。

**触发信号**：Desktop UI 测试中 WebView2 初始化失败。

### RSK-006 gRPC 长连接稳定性（中）

**风险**：单条双向流承载全部通信，任一子流的异常可能影响整条连接；网络设备可能中断空闲连接。

**影响**：节点频繁重连、终端断流。

**应对**：
* 心跳 10 秒（`REQ-PLT-040` 相关）；
* 子流异常不终止主流；
* 每子流独立背压窗口；
* 重连后对账（`Reconcile`）；
* 容量测试包含长时间空闲后的活跃度检查。

**触发信号**：节点在无网络故障时出现周期性重连。

### RSK-007 分片上传的正确性（中）

**风险**：并发分片、断点续传、原子替换的组合容易出现竞态。

**影响**：文件损坏。

**应对**：每片带校验和；合并前逐片校验；合并到临时文件后原子替换；集成测试模拟乱序、重复与中断。

**触发信号**：上传后文件哈希与源不一致。

### RSK-008 HMCL 发布瞬间的一致性（中）

**风险**：客户端持有旧 manifest 时，`overrides/` 已切到新 Release。

**影响**：玩家启动被阻止一次。

**应对**：历史回退查找（`REQ-HMC-032`）+ 内容寻址存储使多数文件天然共享；文档建议低峰期发布。**已接受该残余风险。**

**触发信号**：发布后短时间内 `overrides/` 的 404 计数上升。

### RSK-009 Windows 文件锁（中）

**风险**：运行中的 Java 进程锁定 JAR 与部分文件，导致删除、重命名、移动失败。

**影响**：模组管理与文件操作在实例运行时体验受损。

**应对**：
* 运行中禁用删除、对停用给出警告（`REQ-MOD-014`）；
* 失败时返回 `file-locked` 专用错误码与具体说明；
* 集成测试在真实持有文件句柄的情况下验证错误路径。

**触发信号**：用户反馈通用系统错误而非明确说明。

### RSK-010 长路径（中）

**风险**：实例工作目录 + 深层模组配置路径可能超过 260 字符。

**影响**：文件操作失败。

**应对**：
* 全程使用支持长路径的 API 与 `\\?\` 前缀（仅在内部使用，不接受来自用户的该前缀）；
* 应用清单启用长路径感知；
* HMCL 发布对超长相对路径给出警告与拦截（第 12 节的阈值）；
* 集成测试构造超长路径。

**触发信号**：路径相关的意外失败。

## 2. 产品与范围风险

### RSK-020 需求覆盖遗漏（高）

**风险**：262 条需求跨 15 个域，实现时遗漏。

**应对**：追溯矩阵（`requirements-traceability.md`）在每个阶段更新；文档一致性检查断言不存在「被引用但未定义」与「已定义但未映射」的需求。

### RSK-021 双端一致性偏移（高）

**风险**：Web 与 Desktop 分阶段实现，容易出现字段、动作或文案差异。

**应对**：机器可读的界面契约 + 两端一致性测试（`REQ-DSK-050`）；契约变更走受保护文档流程。

**触发信号**：一致性测试出现差异条目。

### RSK-022 范围蔓延（中）

**风险**：实现过程中引入被明确排除的能力（模组市场、Docker、通用进程托管）。

**应对**：`decision-baseline.md` 为不可协商基线；代码评审与文档一致性检查中包含排除项的关键词扫描。

### RSK-023 界面规格与实现脱节（中）

**风险**：`information-architecture.md` 的页面规格在实现中被简化。

**应对**：契约驱动 + 端到端测试覆盖每个页面的关键区块与动作。

## 3. 安全风险

### RSK-030 路径穿越防护不完整（高）

**风险**：Windows 路径的变体众多（UNC、设备路径、ADS、8.3 短名、重解析点、大小写、尾随点与空格）。

**应对**：统一的路径校验服务；Agent 侧独立重新校验（不信任控制平面）；`SEC-140` 覆盖九类拒绝；把 8.3 短名与尾随点空格纳入用例。

### RSK-031 秘密泄露（高）

**风险**：秘密出现在日志、事件、错误消息或诊断导出中。

**应对**：统一脱敏中间层；`SEC-330` 对每种秘密类型单独断言。

### RSK-032 HMCL 令牌模型的固有弱点（中）

**风险**：HMCL 不发送鉴权头，令牌只能编码在 URL 中，可能出现在配置、日志与截图中。

**应对**：已在文档中明示该模型不适用于高敏感内容；提供轮换与吊销；访问统计中不存完整 IP。**已接受该残余风险。**

### RSK-033 Desktop 本机免登的账户边界（中）

**风险**：同一 Windows 账户下的任意进程都能换取该用户的 Servitium 会话。

**应对**：管道 ACL、SID 绑定、可执行文件路径校验、短期令牌。这是 `DEC-11` 的固有代价，已在文档中明示。**已接受该残余风险。**

### RSK-034 SSRF 防护绕过（高）

**风险**：DNS rebinding、重定向、IPv6 映射地址、非常规主机名表示（十进制 IP、八进制、`0x` 形式）。

**应对**：解析后绑定到已校验 IP；逐跳重校验；主机名规范化后再判断；`SEC-190` … `SEC-193` 覆盖。

## 4. 工程与流程风险

### RSK-040 测试不稳定（高）

**风险**：涉及进程、网络与文件系统的测试容易出现随机失败。

**应对**：禁止 `Sleep` 等待；显式轮询 + 超时；随机端口；独立临时目录；连续 3 次完整运行必须全部通过（`build-and-validation.md` 5.3）。

**触发信号**：同一提交的两次运行结果不同。

### RSK-041 权限阻塞导致验收不完整（高）

**风险**：需要管理员权限的验收项被跳过。

**应对**：`Validate.ps1` 阶段 22 无权限时**失败而非跳过**；权限阻塞流程要求停止并请求用户协助。

### RSK-042 生成代码与来源不一致（中）

**风险**：OpenAPI 客户端、protobuf、文案资源的生成产物被手工修改或未及时重新生成。

**应对**：`Generate.ps1 -Verify` 把产物生成到独立临时目录，并对目标文件集合与逐字节内容做比较；结果不受工作树中其他未提交修改影响。

### RSK-043 阶段门禁被绕过（中）

**风险**：为了推进而在后端未验收时开始前端。

**应对**：阶段 18 是硬门禁；阶段 20 的前置条件明确要求阶段 18 通过；`current-status.md` 记录门禁状态。

### RSK-044 文档基线漂移（中）

**风险**：编码 Agent 修改受保护文档以迎合实现。

**应对**：受保护文档清单 + 变更请求流程 + 文档一致性检查中的「受保护文档变更需有已批准的变更请求」检查。

### RSK-045 依赖不可达（中）

**风险**：NuGet 或 npm 源不可访问。

**应对**：锁定文件 + 包源映射；不可达时报告并请求协助，不得降级或跳过依赖。

## 5. 交付风险

### RSK-050 MSI 安装、升级与卸载（中）

**风险**：服务安装、ACL、升级时的数据保留、卸载时的数据处置容易出错。

**应对**：交付阶段在干净系统上完整验证安装、升级、卸载三条路径；数据保留与删除有独立选项与确认。

### RSK-051 代码签名（中）

**风险**：未签名的产物触发 SmartScreen 警告。

**应对**：交付计划中明确「未签名测试产物」与「代码签名需外部授权」两条路径；签名不由 Agent 自行完成。

### RSK-052 服务恢复策略（低）

**风险**：服务崩溃后未自动恢复。

**应对**：安装器配置恢复策略；交付验证中包含「杀死服务后自动恢复」的检查。
