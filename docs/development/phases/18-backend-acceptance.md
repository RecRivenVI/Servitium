# 阶段 18：后端完整自主验收

## 1. 阶段目的

在开始正式前端开发之前，确认后端已完整、正确、安全、可在容量目标下稳定运行。本阶段是**硬门禁**。

## 2. 需求编号

本阶段不新增需求，而是验收后端范围内的全部需求：`REQ-PLT-*`、`REQ-IDN-*`、`REQ-NOD-*`、`REQ-JRE-*`、`REQ-INS-*`、`REQ-TRM-*`、`REQ-FIL-*`、`REQ-CFG-*`、`REQ-MOD-*`、`REQ-SCH-*`、`REQ-USR-*`（服务端部分）、`REQ-HMC-*`、`REQ-SEC-*`。

## 3. 前置条件

* 阶段 17 完成条件全部满足；
* 阶段 10–17 的动态记录已更新；
* `docs/testing/requirements-traceability.md` 中后端需求已全部映射到实现与测试。

## 4. 范围

* 运行完整验证入口；
* 完成 `docs/testing/backend-acceptance.md` 的全部检查项；
* 容量测试；
* 安全负向测试全量；
* 故障恢复测试；
* 补齐缺失的测试与修复发现的缺陷；
* 更新验收矩阵与追溯矩阵。

## 5. 非目标

* 不开始正式前端开发（`Servitium.Web` 与 `Servitium.Desktop` 的业务实现）；
* 不做界面级验证；
* 不进入交付。

允许的例外：为验证后端而编写的最小化脚本或临时页面，不构成正式前端开发，且不得保留在仓库中。

## 6. 需要创建的项目或目录

无新增项目。可能需要在既有测试项目中补充测试。

## 7. 需要实现的类型或模块

无新增业务模块。可能需要：

* 补充测试用例；
* 修复缺陷；
* 补充容量测试的负载生成器（放在 `tests/Servitium.EndToEndTests` 或独立的容量测试项目中）。

## 8. 数据模型

无变更。若验收中发现模型缺陷，修复并补迁移。

## 9. API 或事件

无新增。若验收中发现契约缺陷，修复并更新 OpenAPI 与生成客户端。

## 10. 实施顺序

1. 用 `eng/Validate.ps1 -Profile BackendGate -Stages 1-6,9-14,16-18,21` 运行非提权部分作前置诊断（该结果不作为门禁证据）；
2. 逐条完成 `docs/testing/backend-acceptance.md` 的检查表；
3. 补齐缺失的测试；
4. 运行容量测试（30 分钟）；
5. 运行故障恢复测试；
6. 运行全量安全测试；
7. 修复全部发现的缺陷并回归；
8. 取得所需权限后运行 `eng/Validate.ps1 -Profile BackendGate`；无权限时按权限阻塞流程请求用户协助；
9. 再连续运行 2 次 `BackendGate`，确认三次完整结果全部通过且无随机失败；
10. 更新 `docs/testing/acceptance-matrix.md` 与 `requirements-traceability.md`；
11. 更新 `docs/records/current-status.md` 标记后端验收通过。

## 11. 关键算法

无。

## 12. Windows 平台事项

平台矩阵要求：下列测试必须在 **Windows 11** 与至少一个 **Windows Server**（2022 或 2025）上各运行一次：

| 测试族 | 理由 |
| --- | --- |
| ConPTY 相关（`INT-580`、`INT-590`） | 版本差异（`RSK-001`） |
| Job Object 相关（`INT-520`、`INT-530`、`SEC-230`、`SEC-231`） | 版本与安全软件差异（`RSK-002`） |
| Windows 服务宿主与关机（`INT-670`） | 服务模型差异 |
| 路径与长路径（`INT-980`） | 文件系统配置差异 |
| Java 探测（`INT-350`） | 注册表布局差异 |

若无法获得第二个平台，必须**停止并请求用户协助**，不得以「行为应当相同」为由跳过。

## 13. 安全要求

`docs/architecture/security-model.md` 第 14 节的全部 `SEC-*` 测试必须实际运行并通过。

不允许：以静态审查代替运行、降低断言、标记为「已知限制」而不修复（除非该项在 `risk-register.md` 第 7 节的已接受残余风险中，且有明确的文档说明）。

## 14. 自动化测试

全量运行既有的 `Unit`、`Architecture`、`Contract` 分类。

新增或补齐：

| 编号族 | 内容 |
| --- | --- |
| `CAP-001` … | 容量测试（见第 15 节） |
| `REC-001` … | 故障恢复测试（见第 15 节） |

## 15. 集成测试

### 15.1 容量测试（分类 `Capacity`）

在容量目标下运行至少 30 分钟：

| 编号 | 内容 | 断言 |
| --- | --- | --- |
| `CAP-001` | 8 个 Agent 同时在线 | 全部 `Online`，心跳正常，无重复注册 |
| `CAP-002` | 64 个实例创建、启动、停止 | 全部成功；状态正确 |
| `CAP-003` | 20 个并发会话执行典型操作 | 无 `429` 误伤；P95 列表延迟 < 300 ms |
| `CAP-004` | 8 个并发终端持续输出 | 无非预期丢失；端到端延迟 P95 < 200 ms |
| `CAP-005` | 持续 30 分钟 | 控制平面工作集增长 < 20%；句柄与连接数无单调增长 |
| `CAP-006` | 并发文件传输 | 受配额与限速约束；无损坏 |
| `CAP-007` | HMCL 端点并发读取（模拟 64 并发 × 多客户端） | 无限流误伤；无 5xx |

### 15.2 故障恢复测试

| 编号 | 场景 | 断言 |
| --- | --- | --- |
| `REC-001` | 控制平面停止后重启 | Agent 自动重连；实例未受影响；对账正确；中断的长操作被标记 |
| `REC-002` | Agent 停止后重启 | 实例进程树被回收；重启后按自动启动配置恢复；对账正确 |
| `REC-003` | Agent 进程被强杀 | 实例进程树在 5 秒内消失 |
| `REC-004` | 网络中断后恢复 | Agent 按退避重连；离线期间的计划任务执行历史被上报 |
| `REC-005` | 控制平面离线期间的计划任务 | 照常执行 |
| `REC-006` | 数据库文件被占用 | 启动时给出明确错误而非崩溃 |
| `REC-007` | 磁盘写满 | 写操作返回 `disk-space-insufficient`；无数据损坏 |
| `REC-008` | 迁移失败 | 拒绝启动并给出明确错误；备份可用 |
| `REC-009` | 内容库对象丢失 | 完整性巡检检出并告警 |
| `REC-010` | 实例工作目录被外部删除 | 状态与操作给出明确错误，不崩溃 |

### 15.3 端到端（后端侧）

| 编号 | 内容 |
| --- | --- |
| `E2E-B01` | 完整流程：初始化 → 节点注册 → Java 登记 → 创建实例 → 启动 → 终端 → 文件 → 配置 → 模组 → 计划任务 → 停止 → 删除登记 |
| `E2E-B02` | HMCL 完整流程：创建 Channel → 归档发布 → 真实客户端安装 → 新增/修改/删除发布 → 客户端更新 → 回滚 → 客户端回退 |
| `E2E-B03` | 权限流程：创建 User → 授权 → 操作 → 撤销 → 被拒且会话被关闭 |

## 16. 人工测试

本阶段原则上不需要用户参与，除非：

* 需要提升权限的阶段无法执行；
* 平台矩阵缺少第二个 Windows 版本；
* 真实 HMCL 客户端需要图形环境。

上述情况按权限阻塞流程请求用户协助，请求内容必须完整（见 `development-workflow.md` 第 7 节）。

## 17. 调试启动方式

```powershell
# 后端门禁完整验证（包含提权阶段）
./eng/Validate.ps1 -Profile BackendGate

# 分类运行
./eng/Test.ps1 -Category Capacity
./eng/Test.ps1 -Category Security
./eng/Test.ps1 -Category EndToEnd
```

## 18. 验收责任方

**编码 Agent 自主验收**，但必须实际运行，不得只审查代码。

## 19. 完成条件

1. `eng/Validate.ps1 -Profile BackendGate` 全量运行通过，退出码 0，所有必需检查均已执行；
2. `docs/testing/backend-acceptance.md` 的全部检查项完成且有证据（命令、输出、产物路径）；
3. 容量测试 `CAP-001` … `CAP-007` 全部通过；
4. 故障恢复测试 `REC-001` … `REC-010` 全部通过；
5. 全部 `SEC-*` 安全测试通过；
6. 端到端 `E2E-B01` … `E2E-B03` 通过；
7. 平台矩阵要求的测试在两个 Windows 版本上均通过；
8. 需要提升权限的阶段已执行（或已按流程请求并由用户完成）；
9. 连续 3 次完整验证无随机失败；
10. 覆盖率门禁通过；
11. 依赖漏洞扫描无高危项；
12. `docs/testing/acceptance-matrix.md` 中后端项全部为通过状态并附证据；
13. `docs/testing/requirements-traceability.md` 中后端需求全部映射到实现与通过的测试；
14. 无未解决的高严重度问题（`docs/records/problem-log.md`）。

## 20. 禁止提前进入下一阶段的条件

**本阶段是硬门禁。** 下列任一条件成立即不得进入阶段 20：

* 完成条件中任一项未满足；
* 存在被跳过的测试；
* 存在以静态审查代替运行的验收项；
* 存在未修复的安全测试失败；
* 存在随机失败的测试；
* 容量测试未在容量目标下运行；
* 需要提升权限的验收项被跳过而非请求用户协助；
* 追溯矩阵存在未映射的后端需求。
