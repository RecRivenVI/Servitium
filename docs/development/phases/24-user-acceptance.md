# 阶段 24：用户协作验收

## 1. 阶段目的

由用户在可调试的测试环境中实际使用 Servitium，确认产品达到可接受的状态。本阶段是**硬门禁**：用户未明确确认通过时，不得标记验收完成，也不得进入交付。

## 2. 需求编号

全部需求的最终确认。重点是无法完全自动化的部分：托盘与系统通知的实际观感、真实 Minecraft 服务端的兼容性、真实 HMCL 客户端的完整体验、界面文案与交互的可用性。

## 3. 前置条件

* 阶段 23 完成条件全部满足；
* `eng/StartAcceptanceEnvironment.ps1` 可用；
* 用户验收材料齐备；
* Agent 已完成的测试有明确记录。

## 4. 范围

* 搭建并启动用户验收环境；
* 向用户提交完整的测试请求；
* 陪同用户完成 `docs/testing/user-testing-procedure.md` 的全部流程；
* 记录用户反馈；
* 修复用户发现的问题并回归；
* 取得用户的明确验收确认。

## 5. 非目标

* 不新增功能（除非用户明确要求且走变更请求流程）；
* 不进入交付（交付需用户另行明确启动）。

## 6. 需要创建的项目或目录

无。

## 7. 需要实现的类型或模块

无新增。可能需要修复用户发现的缺陷。

## 8. 数据模型

无变更。

## 9. API 或事件

无新增。

## 10. 实施顺序

1. 启动验收环境并自检（全部组件在线、测试数据就绪）；
2. 向用户提交测试请求（内容见第 16 节）；
3. 用户按流程测试，Agent 保持环境可用并随时提供日志与说明；
4. 收集用户反馈，逐条记入 `docs/records/problem-log.md`；
5. 按严重度修复问题：
   * 阻断性与高严重度：必须修复并回归后重新请求确认；
   * 中低严重度：与用户确认是否本轮修复或记录为已知限制；
6. 修复后重跑相关测试与 `eng/Validate.ps1 -Profile FrontendGate`；
7. 请求用户最终确认；
8. 用户明确确认通过后，销毁验收环境并清理测试数据；
9. 更新记录并等待用户明确启动交付。

## 11. 关键算法

无。

## 12. Windows 平台事项

* 验收环境需要交互式桌面会话（Desktop 与托盘、通知）；
* 建议在 Windows 11 上进行 Desktop 部分的验收；
* 若用户希望验证 Windows Server 上的服务端行为，需要用户提供环境。

## 13. 安全要求

| 项 | 说明 |
| --- | --- |
| 数据隔离 | 使用独立测试数据库与测试目录；**不得指向用户的真实实例或真实数据** |
| 账号 | 测试账号仅用于本次验收；环境销毁即失效 |
| 网络 | 验收环境默认仅监听回环；若用户要求验证远程访问，需要用户明确同意并配置 TLS |
| 清理 | 验收结束后删除测试数据库、测试目录、测试实例与测试 Channel；确认不残留进程 |

## 14. 自动化测试

本阶段不新增自动化测试。修复缺陷时必须补充回归测试。

## 15. 集成测试

修复后重跑：

* 与缺陷相关的单元、集成、端到端测试；
* `eng/Validate.ps1 -Profile FrontendGate` 全量。

### 16.2 用户测试流程

见 `docs/testing/user-testing-procedure.md`。覆盖：

* 首次初始化与登录（含 TOTP）；
* 节点接入与管理；
* Java 运行时探测与登记；
* 三种方式创建实例；
* 启动、控制台、发送命令、停止、强制终止；
* 崩溃与自动重启；
* 文件管理全套操作；
* 配置结构化编辑与无损保存（复核注释与顺序）；
* 模组管理（含运行中的文件锁提示）；
* 计划任务；
* 用户创建与授权、撤销的即时生效；
* 仪表盘编辑与重置；
* 系统设置各分组；
* HMCL 发布、真实客户端安装与更新、回滚；
* Desktop 专项：单实例、关闭到托盘、退出语义、托盘菜单、系统通知、深链接、独立终端、拖放上传；
* 双端一致性的主观确认；
* 语言切换。

## 17. 调试启动方式

```powershell
./eng/StartAcceptanceEnvironment.ps1
# 停止
./eng/StartAcceptanceEnvironment.ps1 -Stop
```

## 18. 验收责任方

**用户**。Agent 负责提供环境、材料、支持与修复。

## 19. 完成条件

1. 用户完成 `docs/testing/user-testing-procedure.md` 的全部流程；
2. 用户发现的全部阻断性与高严重度问题已修复并回归；
3. 中低严重度问题已与用户确认处置（本轮修复或记录为已知限制）；
4. 修复后 `eng/Validate.ps1 -Profile FrontendGate` 全量通过；
5. **用户明确确认验收通过**；
6. 验收环境已销毁，测试数据已清理，无残留进程；
7. `docs/testing/acceptance-matrix.md` 中用户验收项标记为通过并记录确认时间；
8. `docs/records/current-status.md` 记录用户验收通过、等待用户明确启动交付。

## 20. 禁止提前进入下一阶段的条件

**本阶段是硬门禁。**

* 用户未明确确认通过；
* 存在未修复的阻断性或高严重度问题；
* 验收环境污染了用户的真实数据；
* 用户反馈未被记录与处置。

**用户确认验收通过后，仍不得自动进入交付。** 交付是独立任务，必须由用户另行明确要求启动，见 `docs/delivery/delivery-plan.md`。
