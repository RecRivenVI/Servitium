# Servitium 功能规格

本文件是 Servitium 的**需求基线**。每条需求有稳定编号，供架构、界面、开发阶段、测试与追溯矩阵引用。

编号一经分配不再改变含义。作废的需求保留编号并标注「已作废」，不得复用。

## 0. 编号体系与阅读约定

| 前缀 | 领域 |
| --- | --- |
| `REQ-PLT` | 平台与跨领域机制 |
| `REQ-IDN` | 身份、认证与授权 |
| `REQ-NOD` | 节点 |
| `REQ-JRE` | Java 运行时 |
| `REQ-INS` | Minecraft Java 实例 |
| `REQ-TRM` | 终端与进程 |
| `REQ-FIL` | 文件管理 |
| `REQ-CFG` | 配置管理 |
| `REQ-MOD` | 模组与插件 |
| `REQ-SCH` | 计划任务 |
| `REQ-USR` | 用户、仪表盘与治理 |
| `REQ-DSK` | Desktop 专项 |
| `REQ-HMC` | HMCL 分发 |
| `REQ-SEC` | 安全专项 |
| `REQ-I18N` | 本地化 |

每条需求包含：**要求**（必须实现什么）与**验收**（如何判定实现了）。所有「必须」均为强制。

**执行位置**标记：`[S]` 控制平面、`[A]` Agent、`[W]` Web、`[D]` Desktop、`[SD]` 双端共享界面。

## 1. 平台与跨领域机制（REQ-PLT）

### REQ-PLT-001 标识与时间 `[S][A]`

**要求**：所有实体标识使用 `Guid`（version 4）。所有时间使用 `DateTimeOffset` 并以 UTC 存储与传输，界面按客户端时区展示。数据库不存储本地时间。

**验收**：契约测试断言所有 API 时间字段序列化为带偏移量的 ISO 8601 且偏移量为 `+00:00`；架构测试断言领域模型中不存在 `DateTime` 类型的持久化属性。

### REQ-PLT-010 统一错误模型 `[S]`

**要求**：所有 REST 错误响应使用 RFC 7807 Problem Details（`application/problem+json`），包含 `type`、`title`、`status`、`detail`、`instance`，并扩展 `code`（稳定错误码字符串）与 `traceId`。错误码集合在 `docs/architecture/protocols-and-contracts.md` 中固化，界面按 `code` 而非 `detail` 做分支。

**验收**：集成测试覆盖每个稳定错误码至少一次；契约测试断言所有 4xx/5xx 响应符合 Problem Details 结构。

### REQ-PLT-020 长操作 `[S][A][SD]`

**要求**：任何可能超过 5 秒的动作必须以长操作实现：立即返回 `202 Accepted` 与 `OperationId`；进度、阶段与结果通过 `/hubs/v1/events` 推送；可通过 `GET /api/v1/operations/{id}` 查询；支持取消（`POST /api/v1/operations/{id}/cancel`）。每类操作必须定义明确的提交点：提交点前取消必须生效并清理暂存，提交点后或操作已终止时返回 `operation-not-cancellable`，不能把部分完成伪装为已取消。操作记录持久化，控制平面重启后仍可查询终态。至少下列动作是长操作：实例创建、归档上传创建实例、目录删除、压缩、解压、URL 下载、Java 导入、HMCL 归档检查与发布、批量实例操作。

**验收**：集成测试对每类长操作断言 `202` + `OperationId` + 事件序列 + 终态可查询 + 取消生效。

### REQ-PLT-021 幂等 `[S]`

**要求**：所有创建型与状态变更型 POST 接受 `Idempotency-Key` 请求头。同一键在 24 小时内重复提交返回首次结果而不重复执行。

**验收**：集成测试对实例创建、节点令牌生成、HMCL 发布断言重复提交不产生第二个实体。

### REQ-PLT-022 分页 `[S]`

**要求**：所有列表接口使用游标分页，返回 `items` 与 `nextCursor`。默认页大小 50，上限 200。不使用 offset 分页。

**验收**：集成测试断言在数据变动情况下游标分页不重复不遗漏。

### REQ-PLT-030 实时事件 `[S][SD]`

**要求**：控制平面通过 `/hubs/v1/events` 推送事件信封 `{eventId, type, occurredAt, scope, payload}`。客户端订阅按作用域（全局 / 节点 / 实例）过滤，服务端在推送前执行授权校验。断线重连后客户端可携带 `lastEventId` 请求补发最近 N 条（N 默认 200）。

**验收**：集成测试断言无权限客户端收不到对应作用域事件；断线重连补发覆盖测试。

### REQ-PLT-040 协议版本协商 `[S][A]`

**要求**：Agent 与控制平面在握手时交换协议版本。主版本不一致时拒绝连接并在双方日志与节点页给出明确原因；次版本不一致时允许连接并按较低能力集运行。

**验收**：集成测试用降版本 Agent 桩验证拒绝与降级两条路径。

### REQ-PLT-050 容量目标 `[S][A]`

**要求**：在 8 个 Agent、64 个实例、20 个并发会话、8 个并发终端的规模下，全部功能验收通过，控制平面稳态内存占用可预期，无句柄或连接泄漏。

**验收**：容量测试运行至少 30 分钟，断言功能正确、无泄漏、关键接口 P95 延迟在既定阈值内。

## 2. 身份、认证与授权（REQ-IDN）

### REQ-IDN-001 首次初始化与 Owner `[S][SD]`

**要求**：未初始化时所有界面强制进入初始化流程。初始化创建**唯一 Owner**。Owner 不可删除、不可降级、不可禁用。初始化完成后端点永久关闭，重复调用返回 `409`。

**验收**：集成测试断言二次初始化被拒；单元测试断言 Owner 的删除/降级/禁用操作抛出领域异常。

### REQ-IDN-002 初始化安全边界 `[S]`

**要求**：初始化端点仅接受来自回环地址的请求；若控制平面被配置为非回环监听，则必须提供安装时写入受 ACL 保护文件的一次性初始化令牌。

**验收**：集成测试从非回环地址且无令牌时断言 `403`。

### REQ-IDN-003 初始化密码强度 `[S][SD]`

**要求**：Owner 密码最少 12 字符，且不得是常见弱口令列表中的条目。界面提供强度指示。

**验收**：单元测试覆盖长度与弱口令拒绝。

### REQ-IDN-010 用户名密码登录 `[S][SD]`

**要求**：支持用户名 + 密码登录。密码使用 Argon2id 哈希（内存 64 MiB、迭代 3、并行度 2 起，参数可随硬件调整并记录在哈希串中）。登录失败不区分「用户不存在」与「密码错误」。

**验收**：单元测试断言哈希参数与验证正确；集成测试断言两类失败返回相同错误码与相近响应时间。

### REQ-IDN-011 登出 `[S][SD]`

**要求**：登出使当前会话立即失效并清除会话 Cookie。

### REQ-IDN-012 会话 `[S]`

**要求**：Web 会话使用 `Secure`、`HttpOnly`、`SameSite=Strict` Cookie，配合双提交 CSRF 令牌。会话有效期默认 12 小时、滑动续期上限 7 天，均可配置。用户可在个人设置中查看并撤销自己的活动会话；管理员可撤销任意用户的全部会话。

**验收**：集成测试覆盖过期、滑动续期、撤销即时生效。

### REQ-IDN-013 登录页信息 `[S][SD]`

**要求**：登录前可获取：是否已初始化、是否启用 OIDC、提供方显示名与图标、自定义登录页文本。该端点不泄露用户存在性或系统内部信息。

### REQ-IDN-020 TOTP 绑定 `[S][SD]`

**要求**：用户可绑定 TOTP（RFC 6238，SHA-1，6 位，30 秒步长）。绑定流程：生成密钥 → 展示二维码与文本密钥 → 用户输入一次验证码确认 → 绑定生效并展示 10 个一次性恢复码（仅展示一次）。

**验收**：集成测试覆盖绑定、确认失败重试、恢复码消费。

### REQ-IDN-021 TOTP 登录 `[S][SD]`

**要求**：已绑定 TOTP 的用户登录时，密码校验通过后进入独立的验证码步骤。验证码错误计入登录失败限流。恢复码可替代验证码，用后即焚。

### REQ-IDN-022 TOTP 漂移容忍 `[S]`

**要求**：系统设置中可配置时间漂移容忍步数（0–4，默认 1）。

### REQ-IDN-025 API Key `[S][SD]`

**要求**：用户可创建多把 API Key，每把含名称、创建时间、可选过期时间、可选作用域（只读 / 读写）。Key 明文仅在创建时展示一次，服务端只存哈希。可随时吊销。Key 通过 `Authorization: Bearer` 使用，仅用于 REST，不能用于 SignalR 与 Desktop 换票。使用 Key 的请求记录最后使用时间。

**验收**：集成测试断言明文不可二次获取；断言吊销后立即失效；断言 Key 无法建立 SignalR 连接。

### REQ-IDN-026 API Key 总开关 `[S]`

**要求**：系统设置中的总开关关闭时，所有 API Key 立即失效。

### REQ-IDN-027 修改本人资料 `[S][SD]`

**要求**：用户可修改自己的显示名、界面语言与密码。修改密码需要提供当前密码，成功后撤销该用户除当前会话外的全部会话。

### REQ-IDN-030 角色与实例级授权 `[S]`

**要求**：角色为 `Owner`、`Administrator`、`User`、`Disabled`。

* `Owner`：全部权限，唯一，不可删除/降级/禁用；
* `Administrator`：除「修改 Owner」与「移交 Owner」外的全部权限；
* `User`：仅能访问被显式授权的实例，且仅限实例范围内的操作（控制台、文件、配置、模组、计划任务、实例设置中的非危险项）；
* `Disabled`：无法登录，现有会话立即失效。

授权粒度为「用户 × 实例」白名单。

**验收**：授权矩阵测试逐条覆盖「角色 × 端点」的允许与拒绝。

### REQ-IDN-031 统一授权 `[S]`

**要求**：REST、SignalR、文件流与 Agent 指令四条路径共用同一个授权服务。任何新增端点必须经过该服务，架构测试守护。

**验收**：架构测试断言不存在绕过授权服务直接访问仓储的入口点。

### REQ-IDN-032 权限变更即时生效 `[S]`

**要求**：撤销授权、禁用用户、降级角色时，必须在 2 秒内：使该用户相关的 SignalR 订阅失效并断开、拒绝其进行中的文件流、取消其发起且尚未完成的长操作。

**验收**：集成测试建立终端会话后撤销授权，断言连接在 2 秒内被关闭且后续请求返回 `403`。

### REQ-IDN-040 登录限流 `[S]`

**要求**：按用户名与来源 IP 双维度限流。默认策略：同一用户名连续 5 次失败后指数退避（1、2、4、8、16 分钟）；同一 IP 在 10 分钟内 20 次失败后临时封禁 30 分钟。可在系统设置中调整。封禁状态可由 Owner/Administrator 手工解除。

**验收**：集成测试覆盖退避与封禁，断言解除生效。

### REQ-IDN-041 拦截统计 `[S][SD]`

**要求**：仪表盘展示当前被临时封禁的 IP 数与最近 24 小时被拒绝的访问次数。

### REQ-IDN-050 OIDC 开关 `[S][SD]`

**要求**：支持可选的自托管 OIDC 登录，通过标准发现文档配置。**不支持**通用 OAuth 2.0 手工端点模式。

### REQ-IDN-051 OIDC 配置 `[S][SD]`

**要求**：可配置 Issuer、Client ID、Client Secret、回调地址、Scope、身份映射字段。保存前必须成功拉取发现文档，否则拒绝保存并给出具体失败原因。

**验收**：集成测试用本地 OIDC 桩覆盖成功与失败两条路径。

### REQ-IDN-052 提供方展示 `[S][SD]`

**要求**：可配置提供方显示名与本地上传的图标，用于登录页按钮。

### REQ-IDN-053 登录策略 `[S][SD]`

**要求**：可配置「自动跳转到身份提供方」。即使启用，也**必须**保留「使用本地账户登录」的可展开入口，保证 Owner 在身份提供方不可用时仍能登录。

**验收**：界面测试断言该入口在任何配置下都存在。

### REQ-IDN-054 授权发起 `[S]`

**要求**：发起授权时生成并存储 `state` 与 `nonce`，有效期 10 分钟，一次性。

### REQ-IDN-055 回调校验 `[S]`

**要求**：回调时必须校验 `state` 存在且未消费、ID Token 签名与 `iss`/`aud`/`exp`/`nonce`。subject 与本地用户的绑定关系存储在独立表中，按 `(issuer, subject)` 唯一。不接受仅凭邮箱或用户名的隐式匹配。

**验收**：安全测试覆盖 `state` 重放、`nonce` 不匹配、签名无效、subject 冲突四类拒绝。

### REQ-IDN-056 身份绑定 `[S][SD]`

**要求**：已登录用户可把当前账号绑定到外部身份；未绑定的外部身份登录时引导到绑定流程（需提供本地凭据）。不自动创建用户。

### REQ-IDN-057 解绑 `[S][SD]`

**要求**：用户可解绑自己的外部身份；管理员可为任意用户解绑。解绑前必须确认该用户仍有可用的登录方式。

### REQ-IDN-058 身份配置变更告警 `[SD]`

**要求**：修改 Issuer、Client ID 或身份映射字段时，界面必须以危险确认提示「已绑定的用户可能无法登录」。

## 3. 节点（REQ-NOD）

### REQ-NOD-001 节点列表 `[S][SD]`

**要求**：列出全部节点，含显示名、备注、连接状态、最后心跳时间、平台与版本、协议版本、实例统计。支持按状态与名称过滤、分页。

### REQ-NOD-002 节点指标 `[S][A][SD]`

**要求**：Agent 周期性上报 CPU 使用率、物理内存使用与总量、系统盘与数据盘剩余空间、运行时长。上报间隔默认 5 秒，可配置。控制平面保留最近 24 小时的采样用于图表。

**验收**：集成测试断言指标在节点离线后停止更新且状态转为不可达。

### REQ-NOD-010 注册令牌 `[S][SD]`

**要求**：管理员可生成一次性节点注册令牌，含有效期（默认 30 分钟）与可选的预期节点显示名。令牌明文仅展示一次，服务端只存哈希。可提前作废。

**验收**：集成测试断言令牌过期、重复使用、已作废三种情况均被拒。

### REQ-NOD-011 节点属性 `[S][SD]`

**要求**：管理员可编辑显示名、备注、标签、对外可达地址映射、实例默认基路径、Java 数据目录、上传与下载速率上限、URL 下载并发上限、终端输出缓冲上限、优雅关机开关与等待秒数。

### REQ-NOD-012 移除节点 `[S][SD]`

**要求**：移除节点时必须先确认该节点上没有已登记的实例，或由管理员确认「同时删除这些实例的登记（不删除文件）」。移除后节点凭据立即失效。

**验收**：集成测试断言未清空实例时的阻断路径与确认后的级联路径。

### REQ-NOD-013 强制重连 `[S][A][SD]`

**要求**：管理员可要求某节点立即重建连接。Agent 侧自身也在断开后按指数退避自动重连（1、2、4、8、16、30 秒封顶）。

### REQ-NOD-020 节点凭据 `[S][A]`

**要求**：注册成功后控制平面签发长期节点凭据，Agent 持久化到受 ACL 保护的位置。控制平面只存凭据哈希。支持轮换（旧凭据在新凭据被 Agent 确认后立即失效）与吊销（立即断开且无法重连）。

**验收**：集成测试覆盖签发、轮换、吊销三条路径。

### REQ-NOD-021 传输安全 `[S][A]`

**要求**：Agent 到控制平面的连接必须使用 TLS。默认信任系统证书存储；允许管理员在 Agent 侧固定一个证书指纹（pinning）用于自签场景。明文连接仅在两端均位于同一台机器且目标为回环地址时允许。

**验收**：安全测试断言非回环明文连接被拒。

### REQ-NOD-030 对外地址映射 `[S][SD]`

**要求**：每个节点可配置一组对外可达地址映射（内部地址 → 玩家可用地址）。该映射用于在实例详情中展示玩家连接地址、在诊断信息中展示网络拓扑。**不用于**客户端直连节点。

### REQ-NOD-031 传输速率上限 `[S][A][SD]`

**要求**：可为每个节点配置文件上传与下载的速率上限（0 表示不限）。上限作用于该节点上的所有文件传输。

### REQ-NOD-040 版本与协议提示 `[SD]`

**要求**：节点的 Agent 版本与协议版本在列表与详情中展示。协议主版本不兼容时以危险样式标注并给出升级指引。

### REQ-NOD-041 连接状态 `[S][SD]`

**要求**：节点状态取值：`Online`、`Offline`、`Incompatible`、`Revoked`。状态变化推送事件。

### REQ-NOD-042 节点概览信息 `[SD]`

**要求**：节点卡片展示：连接状态、最后心跳、对外地址、实例运行/总数、平台与 Agent 版本、协议版本、节点 ID（可复制）。

## 4. Java 运行时（REQ-JRE）

### REQ-JRE-001 运行时列表 `[S][A][SD]`

**要求**：按节点列出已登记的 Java 运行时，含显示名、版本、主版本号、架构、厂商、可执行文件路径、来源（探测 / 手工 / 导入）、登记时间、被哪些实例使用。

### REQ-JRE-002 系统探测 `[A][SD]`

**要求**：Agent 可按需扫描本机已安装的 Java，来源包括：
1. 常见安装目录（`%ProgramFiles%\Java`、`%ProgramFiles%\Eclipse Adoptium`、`%ProgramFiles%\BellSoft`、`%ProgramFiles%\Microsoft\jdk`、`%ProgramFiles%\Zulu`、`%LocalAppData%\Programs\...`）；
2. 注册表（`HKLM\SOFTWARE\JavaSoft\*`、`HKLM\SOFTWARE\Eclipse Adoptium\*`、`HKLM\SOFTWARE\BellSoft\*`，含 WOW6432Node）；
3. `JAVA_HOME`；
4. `PATH` 中的 `java.exe`。

扫描结果去重（按解析后的真实路径），展示给管理员选择性登记。**不访问任何在线目录。**

**验收**：集成测试在预置了多个假 Java 目录与注册表项的环境中断言全部被发现且去重正确。

### REQ-JRE-010 手工指定 `[A][SD]`

**要求**：管理员可直接填写 `java.exe` 的绝对路径进行登记。

### REQ-JRE-011 导入压缩包 `[A][SD]`

**要求**：管理员可上传 JDK/JRE 的 ZIP 或 tar.gz 压缩包，Agent 解压到 Java 数据目录下的独立子目录并自动定位 `bin\java.exe`。导入是长操作。解包必须应用归档安全检查（`REQ-SEC-050`）。

**验收**：集成测试覆盖成功导入、找不到 `java.exe` 的失败、恶意归档被拒。

### REQ-JRE-012 版本与可执行性验证 `[A]`

**要求**：登记前必须执行 `java -XshowSettings:properties -version` 并解析：`java.version`、`java.vendor`、`java.vm.name`、`os.arch`。解析失败或进程返回非 0 时拒绝登记并给出具体错误。架构必须为 x64 或 arm64；32 位 Java 被拒绝并说明原因。

**验收**：集成测试用真实 Java 与伪造可执行文件分别验证。

### REQ-JRE-020 Java 数据目录 `[A][SD]`

**要求**：每个节点可配置导入型运行时的存放目录，默认位于 Agent 数据目录下。

### REQ-JRE-030 与实例绑定 `[S][A][SD]`

**要求**：每个实例必须绑定一个已登记的 Java 运行时。绑定的运行时被删除或不可用时，实例启动前给出明确错误而不是让 Java 进程失败。

**验收**：集成测试断言绑定缺失时启动被拒并返回专用错误码。

### REQ-JRE-040 删除登记 `[A][SD]`

**要求**：可取消登记任意运行时。若仍被实例使用，必须先展示使用列表并要求确认。

### REQ-JRE-041 删除导入文件 `[A][SD]`

**要求**：仅对来源为「导入」的运行时提供「同时删除已导入的文件」选项。探测与手工指定的运行时**不提供**文件删除入口。

**验收**：集成测试断言探测型运行时不存在文件删除路径。

## 5. Minecraft Java 实例（REQ-INS）

### REQ-INS-001 实例列表 `[S][SD]`

**要求**：按节点列出实例，支持按名称、状态、标签过滤与游标分页。列表项含名称、状态、节点、Java 运行时、监听端口、在线玩家、上次启动时间、CPU 与内存。

### REQ-INS-002 全节点聚合视图 `[S][SD]`

**要求**：提供「全部节点」视图，按节点分组展示实例，每组独立分页并支持「加载更多」。离线节点显示为分组但标注不可达。

### REQ-INS-003 实例详情 `[S][SD]`

**要求**：返回实例的完整配置与运行时信息。`User` 角色看到的详情不包含节点内部路径以外的系统敏感信息（如节点凭据、其他实例信息）。

### REQ-INS-004 标签 `[S][SD]`

**要求**：实例可打多个标签。列表页提供标签云过滤（可多选，可一键清除）。

### REQ-INS-010 新建空实例 `[S][A][SD]`

**要求**：在节点的默认基路径下按实例 `Guid` 创建工作目录，标记 `OwnedByServitium = true`。表单字段：名称、节点、Java 运行时、启动配置、停止命令与超时、标签、备注。

### REQ-INS-011 上传归档创建 `[S][A][SD]`

**要求**：上传 ZIP 归档，通过归档安全检查后解包到新建的工作目录，`OwnedByServitium = true`。长操作，失败时回滚已创建目录。

### REQ-INS-012 附加已有目录 `[S][A][SD]`

**要求**：管理员填写任意绝对路径。Agent 校验：路径存在且是目录、可读写、不是系统关键目录（`C:\Windows`、`C:\Program Files`、驱动器根）、不是其他实例工作目录或其子目录、路径中不含重解析点。通过后标记 `OwnedByServitium = false`。

**验收**：安全测试逐条覆盖上述拒绝条件。

### REQ-INS-013 修改实例 `[S][A][SD]`

**要求**：可修改名称、标签、备注、Java 运行时、启动配置、停止命令与超时、自动启停策略、终端设置、RCON 设置、服务器查询设置、工作目录。修改工作目录不改变实例身份，且必须在实例停止时进行；修改后重新判定 `OwnedByServitium`。

### REQ-INS-014 删除登记 `[S][A][SD]`

**要求**：移除实例记录、其计划任务、其授权关系、其 HMCL 关联。**绝不触碰文件系统。** 需二次确认，确认对话框明确展示工作目录路径并说明该目录将被保留。

### REQ-INS-015 删除工作目录 `[S][A][SD]`

**要求**：仅当 `OwnedByServitium = true` 时提供。前置条件：实例处于 `Stopped`。确认对话框要求键入实例名称。Agent 执行前再次校验目录仍位于受管基路径之下、不是基路径本身、不含重解析点；删除采用逐条枚举，遇到重解析点立即中止并报错。长操作。

**验收**：安全测试断言外部目录无此入口；断言含目录联接的目录删除被中止；断言基路径本身不可删除。

### REQ-INS-020 默认基路径 `[A][SD]`

**要求**：每个节点可配置实例默认基路径。未配置时使用 Agent 数据目录下的 `Instances` 子目录。

### REQ-INS-021 端口检查 `[S][A][SD]`

**要求**：实例可登记其主要监听端口。保存与启动前，Agent 检查该端口在本机是否已被其他进程或其他 Servitium 实例占用，冲突时给出警告（不阻断，因为端口可能由配置文件动态决定）。

### REQ-INS-030 批量操作 `[S][SD]`

**要求**：支持批量启动、停止、重启、强制终止、删除登记。批量操作以长操作实现，逐项报告成功与失败。**不提供批量删除工作目录。**

**验收**：集成测试断言部分失败时其余项继续执行且结果逐项可见。

### REQ-INS-040 启动 `[S][A]`

**要求**：状态机 `Stopped → Starting → Running`。启动前：校验 Java 运行时可用、工作目录可访问、EULA 已同意。在独立 Job Object 中启动进程。

### REQ-INS-041 停止 `[S][A]`

**要求**：停止序列固定为：向标准输入写入停止命令（默认 `stop`）→ 等待 `StopTimeoutSeconds`（默认 60）→ 发送 `CTRL+BREAK` → 再等 5 秒 → 关闭 Job Object 强制回收。每一步的转换写入操作日志。

**验收**：集成测试用不响应停止命令的测试服务端验证完整降级序列。

### REQ-INS-042 重启 `[S][A]`

**要求**：等价于「停止 → 等待完全停止 → 启动」，作为单个长操作呈现。

### REQ-INS-043 强制终止 `[S][A]`

**要求**：直接关闭 Job Object，回收整棵进程树。需二次确认，确认文案说明可能导致存档损坏。

**验收**：集成测试启动会派生子进程的测试服务端，断言强制终止后整棵进程树消失。

### REQ-INS-050 更新动作 `[S][A]`

**要求**：实例可配置一个「更新动作」，取值为：无、执行指定的服务端 JAR 替换、同步关联的 HMCL Channel 内容。**不提供任意命令执行形式的更新命令。**

### REQ-INS-051 执行更新 `[S][A][SD]`

**要求**：在实例停止时触发更新动作，长操作，执行前自动备份被替换的文件。

### REQ-INS-060 服务器状态查询 `[S][A][SD]`

**要求**：按配置的地址与端口执行 Minecraft Server List Ping，解析版本、MOTD、在线玩家数、最大玩家数、玩家样本。默认地址 `127.0.0.1`，端口取实例登记端口。查询间隔默认 15 秒，仅在实例运行时执行。

**验收**：集成测试用协议桩验证解析正确；断言查询失败不影响实例状态。

### REQ-INS-061 RCON `[S][A][SD]`

**要求**：可配置启用 RCON、地址、端口、密码。启用后提供在控制台侧栏中通过 RCON 发送命令的入口，以及查看在线玩家列表的能力。密码在存储与日志中脱敏，界面上默认隐藏并需显式点击查看。

**验收**：集成测试用 RCON 协议桩验证认证、命令、断线重连。

### REQ-INS-062 自动启动 `[S][A]`

**要求**：可配置实例在 Agent 启动后自动启动，可配置启动延迟（0–600 秒）。

### REQ-INS-063 自动重启 `[S][A]`

**要求**：可配置崩溃后自动重启、最大重启次数（-1 为不限）与重启间隔。达到上限后停止重启并推送告警事件。计数在成功运行超过阈值时长（默认 10 分钟）后重置。

**验收**：集成测试用会立即崩溃的测试服务端验证计数、上限与重置。

### REQ-INS-064 EULA `[S][A][SD]`

**要求**：启动前检查工作目录中的 `eula.txt`。未同意时阻断启动并弹出说明，用户确认后由 Agent 写入 `eula=true`（保留文件中其余内容）。该确认写入操作日志。

### REQ-INS-065 运行账户 `[S][A][SD]`

**要求**：可为实例指定以特定 Windows 账户运行。账户凭据必须在目标节点上通过 Agent 的本地交互式凭据命令登记：密码从安全提示读取，不得出现在命令行参数、环境变量或配置文件中；登记后以 DPAPI（机器范围）加密存储，并返回不含秘密的别名与账户显示名。控制平面只保存凭据别名，实例配置也只引用别名；Web、Desktop、REST 与 gRPC 均不接收或传输 Windows 密码。未配置别名时以 Agent 服务账户运行。

**验收**：安全测试断言凭据不出现在命令行、环境变量、控制平面数据库、gRPC 消息、日志、API 响应或诊断导出中；别名不存在或 DPAPI 解密失败时拒绝启动并返回稳定错误码。

### REQ-INS-066 崩溃识别 `[S][A]`

**要求**：进程退出且不是由 Servitium 主动停止触发时，状态转为 `Crashed`，记录退出码与最近的输出片段，推送事件。

### REQ-INS-070 系统关机优雅停止 `[A]`

**要求**：Agent 服务响应系统关机通知，按配置对全部运行中实例执行停止序列。

**验收**：集成测试通过服务停止事件触发并断言实例被优雅停止。

### REQ-INS-071 关机等待时长 `[A][SD]`

**要求**：可配置关机时等待实例停止的总时长（默认 60 秒），超时后强制回收。

### REQ-INS-080 启动配置：结构化向导 `[S][A][SD]`

**要求**：默认以结构化方式配置启动，字段：

| 字段 | 说明 |
| --- | --- |
| Java 运行时 | 从已登记运行时中选择 |
| 最小堆 / 最大堆 | MiB，生成 `-Xms` / `-Xmx` |
| 附加 JVM 参数 | 逐条添加的字符串列表 |
| 启动方式 | `JAR 文件` 或 `@argfile` |
| 服务端 JAR 路径 | 相对工作目录 |
| argfile 路径 | 相对工作目录 |
| 服务端参数 | 逐条添加，常用项如 `nogui` 提供开关 |
| 环境变量 | 键值对列表 |
| 工作目录 | 实例工作目录（只读展示） |

界面实时展示将要执行的完整命令行预览。

**验收**：单元测试对若干配置组合断言生成的参数数组精确匹配预期。

### REQ-INS-081 启动配置：高级原始命令 `[S][A][SD]`

**要求**：提供受限制的原始命令模式：

* 默认**关闭**，需 Owner/Administrator 在系统设置中显式开启；
* 仅 Owner/Administrator 可为实例启用与编辑；
* 输入为参数数组（不是 shell 字符串），Servitium 不经 shell 解释，直接以 `CreateProcess` 参数形式传递；
* 首个参数必须是已登记 Java 运行时的 `java.exe`，不可指定任意可执行文件；
* 启用与每次修改写入安全审计日志；
* 界面上以警告样式呈现。

**验收**：安全测试断言无法通过该模式执行非 Java 可执行文件；断言未开启总开关时无法启用；断言不经 shell 解释（含 `&`、`|`、`>` 的参数被原样传递）。

## 6. 终端与进程（REQ-TRM）

### REQ-TRM-001 终端会话 `[S][A][SD]`

**要求**：客户端连接控制平面的 `/hubs/v1/terminal`，按实例订阅。控制平面校验授权后在与 Agent 的 gRPC 流上打开终端子流。客户端不直连 Agent。

### REQ-TRM-002 ConPTY `[A]`

**要求**：实例进程在 ConPTY 伪终端中运行（可按实例关闭，关闭时使用重定向管道）。初始尺寸默认 164×40，可配置。

### REQ-TRM-003 Job Object 与进程树 `[A]`

**要求**：每个实例的进程置于独立的 Windows Job Object，设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 与 `JOB_OBJECT_LIMIT_BREAKAWAY_OK = false`。Agent 异常退出时，操作系统自动回收整棵进程树，不留不可控的 Java 进程。

**验收**：集成测试杀死 Agent 进程后断言实例进程树在 5 秒内消失。

### REQ-TRM-010 发送命令 `[S][A][SD]`

**要求**：向实例标准输入发送命令。按实例配置的换行模式（LF / CRLF）与输入编码转换。

### REQ-TRM-011 快捷命令 `[S][SD]`

**要求**：实例可配置一组命名快捷命令，在控制台以按钮组呈现，点击即发送。最多 20 条。

### REQ-TRM-012 尺寸调整 `[S][A][SD]`

**要求**：客户端终端尺寸变化时通知 Agent 调整 ConPTY 尺寸。多客户端同时观察时以最小公共尺寸为准。

### REQ-TRM-020 输出推送 `[S][A][SD]`

**要求**：Agent 按批推送输出（默认每 50 毫秒或累计 8 KiB 触发一次），控制平面扇出给全部订阅者。

### REQ-TRM-021 多客户端观察 `[S][SD]`

**要求**：同一实例可被多个会话同时观察。控制台展示当前观察者数量。

### REQ-TRM-022 ANSI 颜色 `[SD]`

**要求**：终端渲染 ANSI SGR 颜色与样式，可按实例关闭。

### REQ-TRM-023 编码 `[A][SD]`

**要求**：可为实例分别配置输入编码与输出编码（UTF-8、GBK、Big5、Shift_JIS、系统 ANSI 代码页）。默认 UTF-8。

### REQ-TRM-024 换行模式 `[A][SD]`

**要求**：可配置 LF 或 CRLF，Windows 默认 CRLF。

### REQ-TRM-030 输出历史 `[A][S]`

**要求**：Agent 为每个运行中实例维护环形输出缓冲，默认上限 1 MiB 与 5000 行（取先到者），可按节点配置。新订阅者连接时先收到全部缓冲内容再接实时流。

### REQ-TRM-031 断线重连 `[SD]`

**要求**：客户端断线后自动重连并重新拉取缓冲，重连期间实例不受影响。

### REQ-TRM-032 独立终端 `[SD]`

**要求**：Web 可在新标签页打开独立终端视图；Desktop 可打开独立终端窗口。

### REQ-TRM-033 会话日志导出 `[S][SD]`

**要求**：可把当前会话缓冲导出为 UTF-8 文本文件，可选择是否保留 ANSI 转义序列。

### REQ-TRM-040 历史日志文件 `[S][A][SD]`

**要求**：可读取实例工作目录中的 `logs/latest.log` 与历史归档日志，支持按行范围读取与关键字搜索。

## 7. 文件管理（REQ-FIL）

所有文件操作严格限定在实例工作目录内。

### REQ-FIL-001 目录列表 `[S][A][SD]`

**要求**：列出目录条目，含名称、类型（文件/目录）、大小、最后修改时间。支持按名称搜索、按各列排序、游标分页。

### REQ-FIL-002 文件系统状态 `[S][A][SD]`

**要求**：返回工作目录所在卷的总容量与可用空间、当前进行中的文件任务数与配额。

### REQ-FIL-003 卷信息 `[A]`

**要求**：仅返回工作目录所在卷的信息。**不枚举系统盘符，不提供跨卷浏览。**

### REQ-FIL-004 面包屑与路径输入 `[SD]`

**要求**：提供面包屑导航；点击空白区域可切换为路径输入框直接键入相对路径。

### REQ-FIL-005 多标签 `[SD]`

**要求**：文件管理支持多个目录标签，可新建与关闭，最多 8 个。

### REQ-FIL-010 新建 `[S][A][SD]`

**要求**：新建空文件与新建目录。名称必须通过合法性校验（`REQ-FIL-071`）。

### REQ-FIL-011 重命名 `[S][A][SD]`

**要求**：支持文件与目录重命名。新名称必须通过 `REQ-FIL-071`；仅改变大小写时使用临时名称完成两步原子重命名；目标已存在时拒绝并返回稳定错误码，不隐式覆盖。

### REQ-FIL-012 复制 `[S][A][SD]`

**要求**：支持文件与目录复制，目录复制为长操作。同名时提供「覆盖 / 保留两者 / 跳过」选项。

### REQ-FIL-013 移动与剪贴板 `[S][A][SD]`

**要求**：支持剪切、复制到剪贴板并在其他目录粘贴。跨目录移动使用文件系统移动语义，跨卷时降级为复制+删除。

### REQ-FIL-014 删除 `[S][A][SD]`

**要求**：删除文件与目录。目录删除为长操作，遇到重解析点立即中止并报错。二次确认展示条目数与总大小。

### REQ-FIL-015 批量操作 `[SD]`

**要求**：多选后可批量删除、复制、剪切、压缩、下载（打包为 ZIP）。

### REQ-FIL-020 分片上传 `[S][A][SD]`

**要求**：上传采用分片会话：创建会话 → 上传分片（每片带校验和）→ 完成合并。会话可跨连接恢复，客户端重连后查询已收分片位图续传。分片大小默认 8 MiB。会话超时 24 小时后自动清理暂存。Agent 侧以临时文件累积，完成时原子替换目标。

**验收**：集成测试模拟中断后续传，断言最终文件哈希正确；断言超时会话被清理。

### REQ-FIL-021 目录上传 `[SD]`

**要求**：Web 支持选择整个文件夹上传并保持相对结构；Desktop 支持拖放文件与文件夹。

### REQ-FIL-022 上传控制 `[SD]`

### REQ-FIL-030 下载 `[S][A][SD]`

**要求**：流式下载，支持 `Range` 与 `206`，支持断点续传。目录下载打包为 ZIP（长操作）。

### REQ-FIL-031 URL 下载 `[S][A][SD]`

**要求**：从 URL 下载文件到当前目录。长操作，展示进度。必须应用 SSRF 防护（`REQ-SEC-030`）。

### REQ-FIL-032 取消 URL 下载 `[S][A][SD]`

### REQ-FIL-033 URL 下载并发 `[A][SD]`

### REQ-FIL-040 压缩 `[S][A][SD]`

### REQ-FIL-041 解压 `[S][A][SD]`

**要求**：解压 ZIP 到当前目录或新建的子目录。长操作。必须应用归档安全检查（`REQ-SEC-050`）。

### REQ-FIL-042 归档编码 `[SD]`

**要求**：解压与压缩时可选择条目名编码：UTF-8、GBK、Big5、Shift_JIS。默认按 ZIP 的 UTF-8 标志位自动判断，未标记时按用户选择。

### REQ-FIL-043 压缩实现 `[A]`

**要求**：使用 .NET 内建 ZIP 实现，**不外挂 7-Zip 或其他外部程序**。

### REQ-FIL-050 文本编辑 `[S][A][SD]`

**要求**：在 Monaco 编辑器中打开与保存文本文件。按扩展名启用语法高亮。

### REQ-FIL-051 文件编码 `[A][SD]`

**要求**：可为实例配置默认文件编码，也可在打开单个文件时临时切换。支持 UTF-8（带/不带 BOM）、GBK、Big5、Shift_JIS、系统 ANSI 代码页。

### REQ-FIL-052 编辑器行为 `[SD]`

**要求**：`Ctrl+S` 保存；有未保存变更时离开给出确认；显示行号、行尾模式与编码。

### REQ-FIL-053 预览 `[SD]`

**要求**：图片文件（png/jpg/gif/webp/bmp）提供内置预览。

### REQ-FIL-054 原子保存 `[A]`

**要求**：保存采用「写临时文件 → 刷盘 → 原子替换」。目标文件的原有时间戳不保留（反映真实修改时间）。

### REQ-FIL-055 编辑大小上限 `[S][SD]`

**要求**：超过 8 MiB 的文件不允许在编辑器中打开，提示下载后编辑。上限可配置。

### REQ-FIL-060 传输限速 `[S][A][SD]`

**要求**：按节点配置的上传与下载速率上限对所有文件传输生效。

### REQ-FIL-061 并发任务上限 `[A][SD]`

**要求**：每节点可配置同时进行的文件任务数上限，默认 4。超出时排队。

### REQ-FIL-062 压缩任务上限 `[A][SD]`

**要求**：每节点可配置同时进行的压缩/解压任务数上限，默认 2；单个归档解压后的总大小上限默认 8 GiB。

### REQ-FIL-063 普通用户文件管理开关 `[S][SD]`

**要求**：系统设置中可关闭 `User` 角色的文件管理能力（默认开启）。关闭后 `User` 的相关端点返回 `403`。

### REQ-FIL-064 磁盘空间预检 `[A]`

**要求**：上传、URL 下载、解压、复制前预估所需空间，目标卷可用空间不足时直接拒绝并给出所需与可用容量。

### REQ-FIL-070 路径安全 `[A]`

**要求**：所有路径参数必须经过：解码 → 归一化 → 拒绝 `..` 逃逸 → 拒绝绝对路径 → 拒绝 UNC 前缀（`\\`）→ 拒绝设备路径（`\\?\`、`\\.\`）→ 拒绝备用数据流（含 `:` 的名称）→ 解析真实路径并确认仍位于实例工作目录之下 → 拒绝路径中任何一级是符号链接、目录联接或其他重解析点。

**验收**：安全测试逐条覆盖上述九类拒绝。

### REQ-FIL-071 文件名合法性 `[A]`

**要求**：拒绝空名、仅空白、以空格或点结尾、包含 `<>:"/\|?*` 或控制字符、以及 Windows 保留设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`，含带扩展名形式）。

### REQ-FIL-072 归档创建实例的路径校验 `[A]`

**要求**：从归档创建实例时，解包目标必须是 `REQ-INS-011` 新建的 Servitium 自有空目录，并通过规范化、受管基路径包含关系与重解析点检查；归档中的每个条目同时执行 `REQ-SEC-050` 的归档安全校验。任一条目失败时删除本次新建的暂存目录与登记，不影响其他实例或外部目录。

### REQ-CFG-001 配置文件识别 `[S][A][SD]`

**要求**：扫描实例工作目录，识别已知的 Minecraft 服务端配置文件。识别清单至少包含：

`server.properties`、`eula.txt`、`ops.json`、`whitelist.json`、`banned-players.json`、`banned-ips.json`、`bukkit.yml`、`spigot.yml`、`paper.yml`、`config/paper-global.yml`、`config/paper-world-defaults.yml`、`purpur.yml`、`pufferfish.yml`、`velocity.toml`、`config/fabric/*.json`（按需展开）、`config/*.toml`（Forge/NeoForge 通用配置）。

**要求**：读取配置文件时返回原始字节对应的文本、检测到的编码与行尾风格、解析格式、结构化字段、未知键以及语法诊断；读取过程不得改写文件。

### REQ-CFG-003 写入 `[S][A][SD]`

**要求**：写入前校验语法与并发版本，创建备份后写入同目录临时文件并原子替换；并发版本不一致时拒绝覆盖并返回冲突。写入必须满足 `REQ-CFG-020` 的无损要求。

### REQ-CFG-010 结构化表单 `[SD]`

**要求**：对已知格式渲染结构化表单，控件类型按字段定义（文本、整数、小数、布尔开关、枚举下拉、多行文本）。未在定义中的键以通用文本控件展示且保留原位置。

### REQ-CFG-011 `server.properties` 字段定义 `[SD]`

**要求**：内置完整的 `server.properties` 字段定义，包含键名、类型、默认值、取值范围或枚举、单位、说明与所属分组（网络、游戏玩法、世界、性能、安全、其他）。字段定义作为数据文件维护并随版本更新。

**验收**：单元测试断言定义文件可被解析且每个字段有类型与说明。

### REQ-CFG-012 支持格式 `[A]`

**要求**：`properties`、JSON、YAML、TOML、纯文本。

### REQ-CFG-013 冲突提示 `[SD]`

**要求**：同一逻辑配置匹配到多个文件或结构化定义不能唯一确定时，页面必须列出全部候选、当前选择与判定依据；用户明确选择前不得写入。

### REQ-CFG-014 原始文本模式 `[SD]`

**要求**：任何配置文件都可切换到原始文本编辑器，并可切回结构化表单。

### REQ-CFG-020 无损往返 `[A]`

**要求**：读取后未做任何修改再保存，文件内容必须**逐字节相同**。做出修改时，仅被修改键所在的行发生变化，其余字节保持原样。具体到各格式：

* `properties`：保留注释行、空行、键的原始顺序、行内 `\` 续行、原有转义与分隔符形式（`=` 或 `:`）；
* JSON：保留键顺序、缩进风格、数字字面量的原始文本（不做 double 往返）、尾随换行；
* YAML：保留注释、缩进风格、引号风格、锚点与别名；
* TOML：保留注释、表与键的顺序、内联表与多行字符串形式；
* 纯文本：字节级保留，仅按声明编码转换。

**验收**：往返测试对每种格式使用至少 10 个真实样本（含中文注释、混合缩进、特殊转义），断言无修改保存后字节相同；断言单键修改后仅目标行变化。

### REQ-CFG-021 写入前备份 `[A]`

**要求**：每次保存前把原文件复制到 Agent 数据目录下的备份区，命名含实例标识、相对路径与时间戳。每个文件保留最近 10 份，超出后按时间淘汰。界面可查看与恢复备份。

### REQ-CFG-022 语法校验 `[A]`

**要求**：保存前按格式解析一次。失败时拒绝写入，返回错误码与行列位置，界面就地提示。

### REQ-CFG-023 原子保存 `[A]`

**要求**：同 `REQ-FIL-054`。

## 10. 计划任务（REQ-SCH）

### REQ-SCH-001 任务列表 `[S][A][SD]`

### REQ-SCH-011 删除 `[S][A][SD]`

**要求**：删除任务前确认任务名称；删除后取消尚未开始的排队执行，已经开始的执行继续完成并保留历史记录。

### REQ-SCH-012 启用与停用 `[S][A][SD]`

**要求**：停用的任务保留定义但不触发。

### REQ-SCH-013 立即执行 `[S][A][SD]`

**要求**：可手工触发一次执行，不消耗剩余次数，结果记入历史。

### REQ-SCH-020 固定间隔触发 `[A]`

**要求**：以秒为单位配置间隔，最小 10 秒。

### REQ-SCH-021 日历触发 `[A]`

**要求**：配置触发时刻（时:分）与星期集合。按节点本地时区计算。

### REQ-SCH-022 指定单次触发 `[A]`

**要求**：配置一个绝对时间点，触发后任务自动停用（不删除）。

### REQ-SCH-023 剩余次数 `[A]`

**要求**：可配置执行次数（-1 为不限）。减至 0 时任务自动停用（不删除），保留历史。

### REQ-SCH-030 有序动作链 `[A]`

**要求**：任务包含 1–10 个有序动作，逐个执行。任一动作失败时按配置决定「中止后续」或「继续执行」，默认中止。

### REQ-SCH-040 数量上限 `[A][SD]`

### REQ-SCH-041 名称约束 `[A]`

**要求**：同实例内名称唯一，长度 1–64，不含控制字符。名称可修改。

### REQ-SCH-042 执行历史 `[A][S][SD]`

**要求**：记录每次触发的开始时间、结束时间、触发来源（定时 / 手工）、逐动作结果、失败原因。每任务保留最近 100 条。

### REQ-SCH-043 重叠策略 `[A][SD]`

**要求**：前次执行未结束而新触发到来时，按配置处理：`跳过`（默认）、`排队`（最多积压 3 次）、`并发`。

### REQ-SCH-050 本地自治 `[A]`

**要求**：任务定义的权威副本存放在 Agent 本地数据库，由 Agent 独立调度与执行。控制平面离线时任务照常执行，执行历史在本地累积并在重连后同步。控制平面保存只读镜像用于展示与编辑；编辑经控制平面下发到 Agent，Agent 确认后生效。重连时双方对账，以 Agent 为准并把差异记入日志。

**验收**：集成测试断言控制平面停止期间任务仍按时执行，且恢复后历史被同步。

### REQ-USR-040 仪表盘布局 `[S][SD]`

### REQ-USR-041 卡片属性 `[SD]`

**要求**：卡片有标题、描述、宽度（12 栅格中的 1–12）与高度档位（迷你/小/中/大/超大/自适应）。核心卡片标记为不可删除。

### REQ-USR-042 编辑模式 `[SD]`

**要求**：进入编辑模式后可拖拽排序、调整宽高、隐藏、新增卡片、编辑标题与描述。编辑模式下所有业务动作禁用。

### REQ-USR-043 升级补齐 `[S]`

**要求**：产品升级新增默认卡片或页面时，对每个用户按布局版本补入尚未出现的条目，同时保留既有顺序、尺寸、标题、描述与隐藏状态；补齐过程可重复执行且结果一致。

### REQ-USR-044 外观设置 `[S][SD]`

**要求**：可配置页面标题、Logo 图片、背景图片、侧栏位置（左侧导航 / 仅顶栏）、登录页自定义文本。图片为本地上传的资源，不接受外部 URL。

### REQ-USR-045 内容卡片 `[SD]`

**要求**：提供文本、图片、链接、时钟、空白五种内容卡片。

### REQ-USR-046 内嵌卡片 `[S][SD]`

**要求**：提供受限的内嵌卡片：仅允许管理员在系统设置中配置的来源白名单中的 URL；受 CSP `frame-src` 约束；不传递任何会话凭据。

**验收**：安全测试断言白名单外的 URL 被拒绝且 CSP 头包含正确的 `frame-src`。

### REQ-USR-050 界面语言 `[S][SD]`

**要求**：可设置系统默认语言；用户可覆盖为个人语言。

### REQ-USR-051 监听端口 `[S][SD]`

**要求**：可配置控制平面监听端口，默认 5344。修改需重启服务生效，界面明示。

### REQ-USR-052 监听地址 `[S][SD]`

**要求**：默认仅监听 `127.0.0.1`。改为非回环地址时，必须同时满足下列之一，否则拒绝保存：
1. 已配置有效的受信 TLS 证书（可加载、未过期、私钥匹配）；
2. 已显式启用「可信反向代理模式」并配置了可信代理网段与代理头。

**验收**：集成测试断言两个前置条件均不满足时保存被拒并返回专用错误码。

### REQ-USR-053 路径前缀 `[S][SD]`

**要求**：可配置应用挂载的路径前缀，用于反向代理子路径部署。

### REQ-USR-054 跨域来源 `[S][SD]`

**要求**：可配置允许的跨域来源列表（精确匹配，不支持通配）。默认为空。

### REQ-USR-055 压缩 `[S][SD]`

**要求**：可开关 HTTP 响应压缩。HMCL 的 `overrides/` 端点**不受**该开关影响，恒不压缩（见 `REQ-HMC-042`）。

### REQ-USR-056 可信代理 `[S][SD]`

**要求**：可配置可信代理网段与用于取真实来源 IP 的请求头。未在可信网段内的请求，其代理头一律忽略。

**验收**：安全测试断言伪造代理头无法绕过 IP 限流与封禁。

### REQ-USR-057 登录页文本 `[S][SD]`

**要求**：可配置登录页标题、说明与支持信息；两种语言分别存储，未配置某语言时回退到该语言的内置文案。内容按纯文本呈现，不解析 HTML 或 Markdown。

### REQ-USR-058 TLS `[S][SD]`

**要求**：可配置证书来源：Windows 证书存储（按指纹）或 PFX 文件路径 + 密码（DPAPI 加密存储）。保存前必须验证证书可加载、未过期、私钥可用。

### REQ-USR-059 资源上传 `[S][SD]`

**要求**：Logo、背景图、身份提供方图标以上传方式提供。限制类型（png/jpg/svg/webp）与大小（2 MiB）。SVG 必须经过消毒（移除脚本、外部引用、事件属性）。

**验收**：安全测试断言含脚本的 SVG 被消毒或拒绝。

### REQ-USR-060 关于信息 `[SD]`

**要求**：展示版本、构建号、许可、仓库链接与文档链接。

### REQ-USR-061 生效方式标注 `[SD]`

**要求**：每项设置标注「立即生效」或「需要重启服务」。

### REQ-USR-062 诊断导出 `[S][SD]`

**要求**：导出脱敏后的诊断包：版本信息、配置（秘密以固定占位符替换）、节点状态、最近 500 条错误日志、系统信息。导出动作写入安全审计。

**验收**：安全测试断言导出内容不含任何密码、令牌、密钥、证书私钥或 RCON 密码。

## 12. Desktop 专项（REQ-DSK）

### REQ-DSK-001 单实例 `[D]`

**要求**：仅允许一个 Desktop 实例运行。再次启动时激活既有窗口（含从托盘恢复）并退出新进程。

### REQ-DSK-002 本机换票 `[D][S]`

**要求**：Desktop 通过受 ACL 保护的本机命名管道向同机的 `Servitium.Server` 请求短期会话。管道 ACL 仅允许 `Authenticated Users` 连接；服务端读取对端进程的 Windows SID 与可执行文件路径，校验 SID 映射到某个未禁用的 Servitium 用户、且可执行文件位于已安装目录。校验通过后签发默认 15 分钟的会话令牌。

**验收**：安全测试断言未映射的 SID 被拒；断言非安装目录的进程被拒；断言管道 ACL 正确。

### REQ-DSK-003 换票不可用时的回退 `[D]`

**要求**：Server 未运行、管道不可用、SID 未映射时，回退到用户名密码登录界面并给出具体原因。Desktop 也可连接远程 Server（此时仅支持账号密码或 OIDC 登录）。

### REQ-DSK-010 Windows 身份映射 `[S][SD]`

**要求**：管理员可为 Servitium 用户绑定一个 Windows SID。同一 SID 只能绑定一个用户。绑定与解绑写入安全审计。

### REQ-DSK-020 Mica 与原生外观 `[D]`

**要求**：主窗口使用 Mica 材质（系统不支持时优雅降级），跟随系统浅色/深色主题与强调色。

### REQ-DSK-021 原生导航 `[D]`

**要求**：使用 WinUI 3 NavigationView，导航项与 Web 侧栏一一对应，支持返回栈与键盘导航。

### REQ-DSK-030 系统托盘 `[D]`

**要求**：托盘图标显示聚合状态（正常 / 有告警 / 已断开）。右键菜单包含：显示主窗口、实例快捷操作子菜单、暂停通知、退出客户端。

### REQ-DSK-031 关闭到托盘 `[D]`

**要求**：关闭主窗口默认隐藏到托盘而非退出。首次关闭时给出一次性说明。可在设置中改为「关闭即退出」。

### REQ-DSK-032 退出语义 `[D]`

**要求**：「退出客户端」明确表示仅退出 Desktop。菜单项旁与确认对话框中说明「服务端与实例将继续运行」。

**验收**：界面测试断言退出后 Server、Agent 与实例进程仍在运行。

### REQ-DSK-033 实例快捷操作 `[D]`

**要求**：托盘子菜单列出最近使用的最多 10 个实例，提供启动、停止、重启与打开控制台。

### REQ-DSK-040 系统通知 `[D]`

**要求**：使用 Windows 应用通知（AppNotification）推送：实例崩溃、自动重启达到上限、节点离线、长操作完成或失败、HMCL 发布完成。可按类别开关。

### REQ-DSK-041 通知聚合 `[D]`

**要求**：同类事件在 60 秒窗口内合并为一条聚合通知，展示条目数与最近一条摘要。

### REQ-DSK-042 通知深链接 `[D]`

**要求**：点击通知直接导航到相关页面（实例控制台、节点详情、长操作详情、发布详情）。

### REQ-DSK-043 通知排队 `[D]`

**要求**：处于全屏/专注助手或用户已暂停通知时，通知进入队列；恢复后以聚合形式呈现，队列上限 50 条。

### REQ-DSK-050 与 Web 的一致性 `[D][W]`

**要求**：Desktop 与 Web 的信息架构、字段、动作、状态、权限与文案完全一致。差异仅允许出现在：响应式布局、托盘、系统通知、单实例、本机免登、独立终端窗口、拖放上传。

**验收**：一致性测试从共享的界面契约文件生成两端的页面/字段/动作清单并逐项比对。

## 13. HMCL 分发（REQ-HMC）

产品级细节见 `hmcl-distribution-specification.md`；协议细节见 `docs/reference/hmcl-auto-update-protocol.md`。

### REQ-HMC-001 Channel 管理 `[S][SD]`

**要求**：创建、编辑、删除 Channel。Channel 含 slug（URL 安全，唯一，创建后不可改）、显示名、描述、可见性（公开 / 令牌保护）、当前 Release 指针。

### REQ-HMC-002 归档上传 `[S][SD]`

**要求**：上传 ZIP 归档作为 Release 的内容来源。分片上传，长操作。

### REQ-HMC-003 归档检查 `[S]`

**要求**：解包前执行归档安全检查（`REQ-SEC-050`）。解包后执行内容检查：路径合法性、大小写重复、路径长度、`.disabled`/`.old` 条目、排除清单命中项。

### REQ-HMC-004 内容过滤 `[S][SD]`

**要求**：按固定排除清单剔除客户端本地状态与危险文件（清单见分发规格）。界面在发布预览中列出被剔除的条目及原因。

### REQ-HMC-005 发布预览 `[S][SD]`

**要求**：发布前展示与当前 Release 的差异：将新增、将覆盖、将删除的文件清单与数量，以及加载器变更提示。删除项以危险样式呈现。

### REQ-HMC-010 不可变 Release `[S]`

**要求**：Release 一经创建即不可修改。内容以内容寻址方式存储，相同哈希的文件在 Release 间共享。Release 含元数据：名称、作者、版本、描述、游戏版本、加载器声明、创建时间、创建者、文件数与总大小。

### REQ-HMC-011 manifest 物化 `[S]`

**要求**：Release 创建时生成并持久化 `server-manifest.json`，生成规则见协议规范第 10 节。生成后自校验：每个条目的文件在存储中存在且哈希匹配。

**验收**：集成测试断言校验失败时 Release 创建被拒绝。

### REQ-HMC-012 发布前门禁 `[S]`

**要求**：发布（把 Channel 指向某 Release）前必须通过：manifest 每条目可读、哈希匹配、无大小写重复、无非法路径、路径长度未超限、加载器声明合法。任一失败即拒绝发布并列出全部问题。

### REQ-HMC-020 原子发布 `[S]`

**要求**：Channel 指针切换在单个数据库事务中完成。切换后立即生效。

### REQ-HMC-021 回滚 `[S][SD]`

**要求**：可把 Channel 指向任意历史 Release。回滚与发布共用同一套预览与门禁。

### REQ-HMC-022 历史保留 `[S][SD]`

**要求**：保留最近 N 个 Release（默认 10，可配置，最小 3）。超出后按时间淘汰，淘汰时清理不再被任何保留 Release 引用的内容对象。当前生效的 Release 永不淘汰。

### REQ-HMC-030 manifest 端点 `[S]`

**要求**：`GET /hmcl/{channel}/server-manifest.json`（令牌保护时为 `/hmcl/{channel}/{token}/server-manifest.json`）。响应规范见协议规范 8.1，其中 `Cache-Control: no-cache` 为强制。

**验收**：契约测试断言响应头恒为 `no-cache` 且不含未来的 `Expires`。

### REQ-HMC-031 内容端点 `[S]`

**要求**：`GET|HEAD /hmcl/{channel}[/{token}]/overrides/{path}`。响应规范见协议规范 8.2。必须支持 UTF-8 百分号编码路径、`Range`、强 ETag（文件 SHA-1）；`Cache-Control` 固定为 `no-cache, no-transform`，不得设置未来的 `Expires`，因为同一 Channel URL 在发布或回滚后可以指向不同内容。

**验收**：契约测试断言缓存头、ETag、`Range`、`HEAD` 与无压缩行为在公开和令牌保护两种路径上完全一致。

### REQ-HMC-032 历史回退查找 `[S]`

**要求**：`overrides/` 请求在当前 Release 中未命中时，在最近 3 个历史 Release 中查找同路径文件；命中且哈希与该历史 Release 记录一致时返回，否则 `404`。用于保护发布瞬间正在进行的客户端更新会话。

### REQ-HMC-040 可见性与令牌 `[S][SD]`

**要求**：公开 Channel 任何人可读。令牌保护 Channel 的令牌编码在 URL 路径中，服务端只存哈希。可轮换与吊销，界面必须以破坏性操作提示「所有已安装玩家将无法启动，需要重新安装」。

### REQ-HMC-041 分发链接 `[SD]`

**要求**：Channel 详情页展示可直接复制的完整链接，且链接**必须**以 `server-manifest.json` 结尾。

### REQ-HMC-042 内容端点不压缩 `[S]`

**要求**：`overrides/` 端点恒不启用响应压缩，以保证客户端断点续传条件成立。

**验收**：契约测试断言即使全局压缩开启，该端点响应也不含 `Content-Encoding`。

### REQ-HMC-050 访问统计 `[S][SD]`

**要求**：按 Channel 与 Release 统计 manifest 请求数、文件请求数、传输字节数、唯一来源数（按 IP 前缀聚合，不存完整 IP）、错误计数。展示最近 7 天与 30 天。

### REQ-HMC-060 与实例关联 `[S][SD]`

**要求**：实例可关联一个 Channel。关联后：实例详情展示当前 Release；提供「从实例工作目录创建新 Release」的入口（按排除清单过滤）；提供「把实例内容同步到 Channel 当前 Release」的更新动作。

### REQ-HMC-070 真实客户端验证 `[S]`

**要求**：端到端验证必须使用真实 HMCL 客户端完成 `docs/reference/hmcl-client-behavior.md` 第 9 节列出的全部测试项。

## 14. 安全专项（REQ-SEC）

本节汇总跨领域的安全要求；每条与 `docs/architecture/security-model.md` 的威胁编号对应。

### REQ-SEC-010 CSRF `[S]`

**要求**：所有非幂等的 Cookie 认证请求必须携带双提交 CSRF 令牌。任何端点不得关闭该校验。

### REQ-SEC-020 传输安全 `[S]`

**要求**：非回环监听必须启用受信 TLS 或可信反向代理模式（`REQ-USR-052`）。启用 TLS 时设置 HSTS（`max-age` 至少 1 年）。

### REQ-SEC-021 内容安全策略 `[S]`

**要求**：设置 CSP：`default-src 'self'`；`script-src 'self'`（不含 `unsafe-inline` 与 `unsafe-eval`，Monaco 的 worker 通过 `worker-src 'self' blob:` 放行）；`style-src 'self' 'unsafe-inline'`（Fluent UI 运行时样式所需，并以 nonce 逐步收紧）；`img-src 'self' data:`；`connect-src 'self'`；`frame-src` 为内嵌卡片白名单；`frame-ancestors 'none'`；`object-src 'none'`；`base-uri 'self'`。

**验收**：契约测试断言 CSP 头存在且不含 `unsafe-eval`。

### REQ-SEC-030 SSRF `[S][A]`

**要求**：URL 下载与 OIDC 协议请求之外，Servitium 不发起任意出站请求。两类请求必须共用同一受限出站 HTTP 实现，并满足：
* 仅允许 `http`/`https`；
* 解析主机名后，对**每一个**候选 IP 校验不属于回环、链路本地（169.254/16、fe80::/10）、私有网段（10/8、172.16/12、192.168/16、fc00::/7）、保留网段、以及节点自身地址——除非管理员在系统设置中把该主机加入私有源白名单；
* 连接时绑定到已校验的 IP（而非重新解析），防止 DNS rebinding；
* 逐跳重定向重新执行全部校验，最多 5 跳；
* 固定连接与读取超时；
* URL 下载遵守下载大小上限；OIDC 发现文档、JWKS 与令牌响应分别使用固定的小型响应上限；
* OIDC 的 Issuer、发现文档声明的端点、JWKS 地址与每次重定向均独立校验；需要访问私有自托管提供方时，必须以主机名 + 端口精确加入私有源白名单。

**验收**：安全测试分别从 URL 下载与 OIDC 两个入口覆盖私有地址、重定向到私有地址、DNS rebinding、超长重定向链四类。

### REQ-SEC-040 本机通道 `[S][D]`

**要求**：见 `REQ-DSK-002`。

### REQ-SEC-050 归档安全 `[S][A]`

**要求**：所有归档解包（实例创建、Java 导入、文件解压、HMCL 归档）必须：
* 逐条目校验目标路径不逃逸目标根（ZIP Slip）；
* 拒绝绝对路径、UNC、设备路径、含 `..` 的条目；
* 拒绝符号链接与硬链接条目；
* 限制条目总数（默认 100000）、解压后总大小（默认 8 GiB）、单条目压缩比（默认 200:1）；
* 限制目录深度（默认 64）；
* 拒绝含 Windows 非法字符或保留设备名的条目名。

**验收**：安全测试使用构造的恶意归档逐条覆盖。

### REQ-SEC-060 秘密脱敏 `[S][A]`

**要求**：下列值在日志、事件、API 响应、错误消息与诊断导出中一律脱敏：密码与哈希、会话令牌、CSRF 令牌、API Key、节点凭据、节点注册令牌、HMCL Channel 令牌、RCON 密码、OIDC Client Secret、TLS 私钥与 PFX 密码、Windows 运行账户密码。

**验收**：安全测试遍历诊断导出与日志样本，断言不出现已知的秘密值。

### REQ-SEC-070 限流 `[S]`

**要求**：对登录、API Key 认证、文件流、HMCL 端点分别配置限流策略。HMCL 端点的阈值必须显著高于单客户端 64 路并发 × 5 次重试。

### REQ-SEC-080 审计不可修改 `[S]`

**要求**：见 `REQ-USR-032`。

## 15. 本地化（REQ-I18N）

### REQ-I18N-001 语言集合 `[S][SD]`

**要求**：首发支持 `zh-Hans` 与 `en-US`。资源结构与流程见 `localization-specification.md`。

### REQ-I18N-002 双端文案一致 `[SD]`

**要求**：Desktop 与 Web 共用同一份文案键与译文来源。

### REQ-I18N-003 服务端消息 `[S]`

### REQ-I18N-004 完备性 `[SD]`
