# 问题日志

本文件是**可持续更新**的动态记录，记录开发与验收过程中遇到的问题及其处置。

## 1. 记录格式

```text
## PB-### <标题>

| 项 | 内容 |
| --- | --- |
| 发现日期 | YYYY-MM-DD |
| 发现阶段 | 阶段编号 |
| 来源 | 自动化测试 / Agent 自查 / 用户反馈 / 运行观察 |
| 严重度 | 阻断 / 高 / 中 / 低 |
| 现象 | 观察到什么 |
| 复现 | 精确到可重复执行的步骤或命令 |
| 影响 | 影响哪些需求、功能或验收项 |
| 根因 | 已定位时填写；未定位时写「排查中」 |
| 处置 | 修复方案或决定 |
| 回归测试 | 补充的测试编号 |
| 状态 | 排查中 / 修复中 / 已修复 / 已接受 / 已关闭 |
| 关闭日期 | YYYY-MM-DD |
| 关联 | 风险编号、需求编号、变更请求编号 |
```

编号 `PB-###` 连续递增，一经分配不复用。

## 2. 规则

| 规则 | 说明 |
| --- | --- |
| 不隐藏问题 | 任何测试失败、随机失败、运行异常都必须登记 |
| 不静默绕过 | 不得通过注释测试、降低断言、放宽超时来「解决」问题 |
| 必须回归 | 每个被修复的问题必须补一条回归测试并记录编号 |
| 随机失败即缺陷 | 不得以重试掩盖；必须定位 |
| 已接受需说明 | 状态为「已接受」时必须写明理由，并确认该项在 `risk-register.md` 第 7 节中有对应的残余风险条目 |
| 阻断与高严重度 | 必须在当前阶段修复，不得推迟到后续阶段 |

## 3. 严重度定义

| 严重度 | 定义 |
| --- | --- |
| 阻断 | 核心流程不可用、数据丢失或损坏、安全问题、门禁无法通过 |
| 高 | 主要功能明显缺陷；有可行的临时规避但影响正常使用 |
| 中 | 次要功能缺陷、体验问题、性能未达标但可用 |
| 低 | 文案、细节、非关键路径的小瑕疵 |
