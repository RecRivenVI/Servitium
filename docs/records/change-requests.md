# 变更请求

本文件是**可持续更新**的动态记录，用于在需要修改**受保护文档**时向用户提出请求并记录裁决。

后续编码 Agent 不得直接修改受保护文档；必须先在此登记并等待用户决定。

**参考证据边界**：编码 Agent 可按 `AGENTS.md` 前往 MCSManager、HMCL、Prism Launcher 与本地整合包发布原型的四个绝对路径实地考察。新证据不得被改写来迎合当前实现；新证据若与受保护文档冲突，或据此需要改变产品、协议、界面、阶段或安全决定，在此提出变更请求，并附仓库提交或非 Git 文件快照、证据路径、运行命令与复现方式。

## 2. 流程

```text
1. 发现需要变更受保护文档的事实或约束
2. 在第 4 节新建条目，填写：当前要求 / 问题 / 建议 / 影响
3. 停止依赖该变更的工作；继续推进不受影响的部分
4. 在阶段报告中向用户提示存在待裁决的变更请求
5. 等待用户裁决
6. 用户批准后，由用户或经用户明确授权的一轮任务修改受保护文档
7. 回到本文件更新裁决结果与实施状态
```

未经用户批准，任何人不得修改受保护文档。

## 3. 记录格式

```text
## CR-### <标题>

| 项 | 内容 |
| --- | --- |
| 提出日期 | YYYY-MM-DD |
| 提出阶段 | 阶段编号 |
| 目标文档 | 需要修改的受保护文档与章节 |
| 当前要求 | 文档目前是怎么规定的（原文引用） |
| 问题 | 为什么当前要求不可行、不正确或不充分；附证据 |
| 建议 | 建议改成什么；给出具体措辞 |
| 影响 | 涉及的需求编号、阶段、测试、其他文档 |
| 替代方案 | 若不变更，可行的替代做法与代价 |
| 紧急度 | 阻断当前阶段 / 影响后续阶段 / 可延后 |
| 状态 | 待裁决 / 已批准 / 已驳回 / 已实施 |
| 用户裁决 | 用户的决定与说明 |
| 裁决日期 | YYYY-MM-DD |
| 实施情况 | 变更后的实际改动 |
```

编号 `CR-###` 连续递增，一经分配不复用。

## 5. 什么情况应该提出变更请求

| 情况 | 是否提出 |
| --- | --- |
| 规格中某项在技术上不可实现 | 是 |
| 规格内部存在矛盾 | 是 |
| 新取得的参考证据与受保护文档或实际运行不符 | 是 |
| 需要新增、删除或重排阶段 | 是 |
| 需要新增或修改需求编号 | 是 |
| 需要改变界面契约（页面、字段、动作） | 是 |
| 需要改变协议、错误码或事件类型 | 是 |
| 需要降低安全要求 | 是（且默认不予批准） |
| 需要删除某个验收项 | 是（且默认不予批准） |
| 选择某个库或内部数据结构 | 否，记入 `decision-log.md` |
| 内部目录组织的细节 | 否，记入 `decision-log.md` |
| 发现并修复缺陷 | 否，记入 `problem-log.md` |
| 阶段实际耗时与预期不同 | 否 |

## 6. 不得通过本文件绕过的事项

| 事项 | 说明 |
| --- | --- |
| `docs/product/decision-baseline.md` 中的 18 条固定决策 | 由用户明确确定，变更请求只能提请用户重新决策，不得自行调整 |
| 「开发完成不自动进入交付」 | 交付必须由用户明确启动 |
| 阶段 18 与阶段 24 的硬门禁 | 不得以变更请求的方式弱化 |
| 「不得跳过测试」「不得以静态审查代替运行」 | 缺权限或缺环境时走权限阻塞流程，不是变更请求 |
