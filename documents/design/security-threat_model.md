# 安全模型

本文件定义 Servitium 的安全设计与威胁应对。每项威胁编号 `THR-###`，并给出**必须存在的测试**。测试编号在 `../../validations/integration-backend/validation.md` 中展开。

## 1. 安全目标

1. 默认部署（回环监听、单机、Owner 一人）在无额外配置下是安全的。
2. 任何提升暴露面的配置变更（非回环监听、公开 HMCL Channel、启用高级原始命令）必须显式、可审计、且伴随强制的前置条件。
3. `User` 角色不能通过任何路径影响其未被授权的实例、其他用户或系统配置。
4. 文件操作不能越出实例工作目录。
5. 秘密不出现在日志、事件、API 响应或诊断导出中。
6. 安全相关事件全部可审计且审计不可篡改。

## 2. 信任边界

```text
┌─ 不受信 ─────────────────────────────────────────────┐
│ 浏览器、HMCL 客户端、外部 URL、上传的归档、公网       │
└──────────────────────────────────────────────────────┘
              │  TLS / 输入校验 / 归档检查
┌─ 半受信 ────────────────────────────────────────────┐
│ 已认证的 User 角色会话                                │
└──────────────────────────────────────────────────────┘
              │  实例级授权
┌─ 受信 ──────────────────────────────────────────────┐
│ Servitium.Server 进程、Servitium.Agent 进程           │
│ 数据目录、内容库、Agent 本地数据库                     │
└──────────────────────────────────────────────────────┘
```

Agent 对 Server 的信任由节点凭据建立；Server 对 Agent 的信任同样由该凭据建立。Agent 不信任来自 Server 的路径参数——所有路径在 Agent 侧独立重新校验。

## 3. 认证

### THR-001 首次初始化被抢占

**威胁**：攻击者在管理员之前访问未初始化的实例并创建 Owner。

**应对**：初始化端点仅接受回环请求；若配置为非回环监听，则要求提供安装时写入受 ACL 保护文件的一次性初始化令牌。初始化完成后端点永久关闭。

**测试**：`SEC-001` 从非回环且无令牌时断言 `403`；`SEC-002` 二次初始化断言 `409`。

### THR-002 口令暴力破解

**应对**：Argon2id 哈希（内存 64 MiB、迭代 3、并行度 2 起）；按用户名与 IP 双维度限流与指数退避；失败不区分用户存在性且响应时间相近。

**测试**：`SEC-010` 退避生效；`SEC-011` IP 封禁生效；`SEC-012` 用户存在性不可枚举。

### THR-003 TOTP 绕过

**应对**：TOTP 验证在密码验证之后的独立步骤中进行，中间态是一个仅能调用 TOTP 端点的受限会话；验证码错误计入限流；恢复码逐个哈希存储且用后即焚；漂移容忍上限 4 步。

**测试**：`SEC-020` 受限会话不能访问业务端点；`SEC-021` 恢复码不可重放。

### THR-004 API Key 泄露与滥用

**应对**：只存 SHA-256 哈希；明文仅创建时返回一次；可设过期与只读作用域；可随时吊销；全局开关可一键停用全部 Key；Key 不能用于 SignalR；每次使用更新最后使用时间以便发现异常。

**测试**：`SEC-030` 吊销即时生效；`SEC-031` Key 无法建立 SignalR 连接；`SEC-032` 只读 Key 无法执行写操作。

### THR-005 OIDC 攻击

**威胁**：`state` 重放、`nonce` 缺失导致的令牌注入、subject 冲突导致的账号接管、ID Token 伪造。

**应对**：
* `state` 与 `nonce` 服务端生成并存储，有效期 10 分钟，一次性消费；
* 校验 ID Token 签名（从发现文档的 JWKS 取密钥，带缓存与轮换）、`iss`、`aud`、`exp`、`iat`、`nonce`；
* 绑定关系按 `(issuer, subject)` 唯一，且一个用户至多绑定一个外部身份；
* **不接受**仅凭邮箱或用户名的隐式匹配，不自动创建用户；
* 首次通过外部身份登录时必须先用本地凭据完成绑定。

**测试**：`SEC-040` `state` 重放被拒；`SEC-041` `nonce` 不匹配被拒；`SEC-042` 签名无效被拒；`SEC-043` subject 已绑定他人时被拒；`SEC-044` 不自动创建用户。

### THR-006 Desktop 本机换票被冒用

**威胁**：同机的低权限进程连接命名管道换取会话。

**应对**：
* 管道 ACL：`SYSTEM` 与服务账户完全控制，`Authenticated Users` 仅连接读写，`Everyone` 无权限；
* 服务端读取对端进程的 Windows SID，必须映射到某个未禁用的 Servitium 用户；
* 服务端读取对端进程的可执行文件完整路径，必须位于已安装目录之内；
* 换得的是 60 秒一次性令牌，再换取 15 分钟会话；
* 管道仅在本机可用（命名管道天然不跨网络）。

**残余风险**：同一 Windows 账户下的任意进程都可换取该用户的会话。这是「Windows 身份即 Servitium 身份」这一决策（`DEC-11`）的固有代价，在文档中明示。

**测试**：`SEC-050` 未绑定 SID 被拒；`SEC-051` 非安装目录进程被拒；`SEC-052` 管道 ACL 断言。

### THR-007 会话固定与 CSRF

**应对**：登录成功后重新生成会话标识；Cookie 为 `Secure`、`HttpOnly`、`SameSite=Strict`；所有非幂等的 Cookie 认证请求要求双提交 CSRF 令牌，任何端点不得关闭；SignalR 连接握手同样校验 CSRF。

**测试**：`SEC-060` 缺失 CSRF 令牌被拒；`SEC-061` 登录后会话标识变化；`SEC-062` 无 CSRF 的 SignalR 握手被拒。

## 4. 授权

### THR-010 越权访问其他实例

**应对**：单一授权服务，四条路径（REST、SignalR、文件流、Agent 指令）统一调用。架构测试断言不存在绕过入口。Agent 侧对每条指令再次校验实例归属（防止控制平面逻辑缺陷放大为节点越权）。

**测试**：`SEC-070` 授权矩阵逐条覆盖「角色 × 端点」；`SEC-071` `User` 访问未授权实例的每类端点均返回 `403`。

### THR-011 权限变更不生效

**威胁**：撤销授权后，已建立的终端会话与文件流仍可继续使用。

**应对**：授权变更触发定向事件与主动断连；进行中的长操作被取消；文件流下一个数据块前重新校验。要求 2 秒内生效。

**测试**：`SEC-080` 终端会话在撤销后 2 秒内被关闭；`SEC-081` 进行中的下载被中止。

### THR-012 Owner 被移除或降级

**应对**：领域层强制：`Owner` 角色的用户不可删除、不可降级、不可禁用；系统中恒有且仅有一个 Owner。移交 Owner 是显式操作，需当前 Owner 的密码 + TOTP 确认，且写入审计。

**测试**：`SEC-090` 三类操作均抛领域异常。

## 5. 传输与浏览器安全

### THR-020 明文传输

**应对**：默认仅监听 `127.0.0.1`。改为非回环时必须满足：已配置有效受信 TLS 证书，或已显式启用可信反向代理模式并配置可信网段与代理头。否则拒绝保存设置。启用 TLS 时设置 HSTS（`max-age` ≥ 1 年）。

**测试**：`SEC-100` 两个前置条件均不满足时保存被拒。

### THR-021 代理头伪造

**威胁**：伪造 `X-Forwarded-For` 绕过 IP 限流与封禁。

**应对**：仅当请求的直接来源 IP 位于配置的可信代理网段内时才采信代理头；否则一律使用连接的直接来源 IP。

**测试**：`SEC-110` 非可信来源的代理头被忽略。

### THR-022 XSS

**应对**：
* CSP：`default-src 'self'`；`script-src 'self'`（无 `unsafe-inline`、无 `unsafe-eval`；Monaco worker 通过 `worker-src 'self' blob:` 放行）；`style-src 'self' 'unsafe-inline'`；`img-src 'self' data:`；`connect-src 'self'`；`frame-src` 为内嵌卡片白名单；`frame-ancestors 'none'`；`object-src 'none'`；`base-uri 'self'`；
* React 默认转义；禁止使用 `dangerouslySetInnerHTML`（lint 规则强制）；
* 用户可控内容（实例名、标签、备注、Channel 描述、卡片文本）在渲染前统一经过消毒；
* 上传的 SVG 资源必须消毒（移除脚本、事件属性、外部引用），或直接拒绝 SVG。

**测试**：`SEC-120` CSP 头断言；`SEC-121` 含脚本的 SVG 被拒或消毒；`SEC-122` 恶意实例名不产生脚本执行。

### THR-023 CORS 滥用

**应对**：默认无允许来源。允许来源为精确匹配的白名单，不支持通配符与正则。`Access-Control-Allow-Credentials` 仅对白名单来源返回。

**测试**：`SEC-130` 未在白名单的来源不返回 CORS 头。

### THR-024 点击劫持

**应对**：`frame-ancestors 'none'` 与 `X-Frame-Options: DENY`。

**测试**：`SEC-131` 断言两项响应头同时存在，且页面不能被同源或跨源框架嵌入。

## 6. 输入与路径安全

### THR-030 路径穿越

**应对**：所有路径参数在 **Agent 侧**（不仅是 Server 侧）经过完整校验链：

1. 百分号解码（若来自 URL）；
2. 拒绝空、拒绝含 NUL 与控制字符；
3. 拒绝绝对路径（含盘符形式与根斜杠形式）；
4. 拒绝 UNC 前缀 `\\`；
5. 拒绝设备路径前缀 `\\?\`、`\\.\`；
6. 拒绝备用数据流（路径段中含 `:`）；
7. 归一化并拒绝 `..` 逃逸；
8. 逐级解析真实路径，拒绝任何一级是符号链接、目录联接或其他重解析点；
9. 确认最终真实路径位于实例工作目录之下。

**测试**：`SEC-140` 逐条覆盖上述九类，共 9 个用例族。

### THR-031 文件名注入

**应对**：拒绝 Windows 非法字符 `<>:"/\|?*`、控制字符、以空格或点结尾的名称、Windows 保留设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`，含带扩展名形式）。

**测试**：`SEC-150` 逐条覆盖。

### THR-032 ZIP Slip

**应对**：归档解包时逐条目按 THR-030 的规则校验目标路径。

**测试**：`SEC-160` 构造含 `../` 条目的归档，断言被拒。

### THR-033 归档链接条目

**应对**：拒绝归档中的符号链接与硬链接条目。

**测试**：`SEC-161`。

### THR-034 ZIP 炸弹

**应对**：限制条目总数（默认 100000）、解压后总大小（默认 8 GiB）、单条目压缩比（默认 200:1）、目录深度（默认 64）。超限即中止并清理已解出的内容。

**测试**：`SEC-162` 高压缩比归档；`SEC-163` 超量条目归档；`SEC-164` 深层嵌套归档。

### THR-035 磁盘耗尽

**应对**：上传、URL 下载、解压、复制前预估所需空间并检查目标卷可用空间；不足时拒绝。节点级配额限制并发任务数与单归档解压上限。

**测试**：`SEC-170` 模拟低可用空间时被拒。

### THR-036 临时文件竞争与残留

**应对**：临时文件创建在受 ACL 保护的数据目录下（不使用系统临时目录）；使用随机文件名；写入完成后原子替换目标；进程启动时清理超期的暂存目录。

**测试**：`SEC-180` 断言临时文件位于数据目录且 ACL 正确；`SEC-181` 断言超期暂存被清理。

## 7. 出站请求

### THR-040 SSRF

**威胁**：通过 URL 下载或恶意 OIDC 配置访问内网服务或云元数据端点。

**应对**：
* 仅允许 `http`/`https`；
* 解析主机名得到全部候选 IP，逐个校验不属于回环、链路本地（`169.254.0.0/16`、`fe80::/10`）、私有网段（`10/8`、`172.16/12`、`192.168/16`、`fc00::/7`）、保留与文档网段、组播、以及节点自身的任何地址；
* 例外：管理员在系统设置中显式配置的私有源白名单（按主机名 + 端口精确匹配）；
* 连接时**绑定到已校验的 IP** 而非重新解析（防 DNS rebinding）；
* 逐跳重定向重新执行全部校验，最多 5 跳；
* 固定连接与读取超时；
* URL 下载遵守下载大小上限；OIDC 发现文档、JWKS 与令牌响应使用独立的固定响应上限；
* OIDC 的 Issuer、发现文档声明的端点、JWKS 地址与重定向逐一重校验；私有自托管提供方必须按主机名 + 端口显式加入白名单，不能仅凭 Issuer 配置隐含放行。

**测试**：`SEC-190` 私有地址被拒；`SEC-191` 重定向到私有地址被拒；`SEC-192` DNS rebinding 被拒；`SEC-193` 超长重定向链被拒。四项测试都从 URL 下载与 OIDC 两个入口执行。

## 8. 进程与命令

### THR-050 命令注入

**应对**：Servitium **从不**通过 shell 启动进程。所有进程创建使用参数数组，由 .NET 直接传给 `CreateProcess`。启动配置的结构化向导生成参数数组；高级原始命令模式的输入本身就是参数数组，不做 shell 解析。

**测试**：`SEC-200` 含 `&`、`|`、`>`、`` ` ``、`$()` 的参数被原样传递给子进程而非被解释。

### THR-051 任意可执行文件执行

**应对**：高级原始命令模式的首个参数必须是**已登记的 Java 运行时**的 `java.exe` 路径（精确匹配已登记路径）。不允许指定任意可执行文件。

**测试**：`SEC-210` 指定其他可执行文件被拒。

### THR-052 高级原始命令被滥用

**应对**：
* 全局开关默认关闭，需 Owner/Administrator 在系统设置中显式开启；
* 仅 Owner/Administrator 可为实例启用与编辑；
* `User` 角色不可见、不可编辑；
* 启用与每次修改写入安全审计（含前后值）；
* 界面以警告样式呈现。

**测试**：`SEC-220` 未开启总开关时启用被拒；`SEC-221` `User` 修改被拒；`SEC-222` 审计条目产生。

### THR-053 进程树逃逸

**威胁**：Java 服务端派生的子进程在强制终止后残留，或在 Agent 崩溃后失控。

**应对**：每个实例的进程置于独立 Job Object，设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` 且禁止 breakaway。Agent 持有句柄；Agent 退出（正常或异常）即由操作系统回收整棵树。

**测试**：`SEC-230` 强制终止后进程树消失；`SEC-231` 杀死 Agent 后进程树在 5 秒内消失。

### THR-054 运行账户凭据泄露

**应对**：以特定 Windows 账户运行的凭据只在目标 Agent 上通过本地交互式安全提示登记，并以 DPAPI（机器范围）加密存储；密码不得进入命令行参数、环境变量、控制平面、REST 或 gRPC，实例只引用不含秘密的凭据别名；凭据不出现在任何日志、事件或诊断导出中。

**测试**：`SEC-240` 使用已知测试密码登记凭据后，遍历进程命令行、环境、控制平面数据库、捕获的 gRPC 消息、日志与诊断导出，断言均不含该值。

## 9. HMCL 分发安全

### THR-060 未授权访问整合内容

**应对**：Channel 可见性为「公开」或「令牌保护」。令牌编码在 URL 路径中（HMCL 不发送任何鉴权头，这是协议限制），32 字节随机值，服务端只存 SHA-256 哈希，可轮换与吊销。

**残余风险**：URL 中的令牌可能出现在玩家的启动器配置、反向代理日志或屏幕分享中。文档中明示该模型不适用于高敏感内容。

**测试**：`SEC-250` 错误令牌返回 `403`；`SEC-251` 轮换后旧令牌失效。

### THR-061 分发端点被用于路径穿越

**应对**：`overrides/{path}` 的 `path` 不映射到文件系统路径——它是 Release 内容清单中的**键**。服务端按精确键查表得到 SHA-1，再从内容库按哈希取文件。因此不存在文件系统层面的路径穿越面。仍对 `path` 做规范校验以拒绝畸形请求。

**测试**：`SEC-260` `../` 与绝对路径返回 `400` 或 `404`，且不读取内容库以外的文件。

### THR-062 分发端点被用于放大攻击

**应对**：按来源 IP 限流（阈值显著高于单客户端 64 并发 × 5 重试）；单连接带宽上限可配置；`HEAD` 不返回正文。

**测试**：`SEC-270` 限流生效且不误伤正常客户端。

### THR-063 恶意归档进入内容库

**应对**：归档安全检查（THR-032/033/034）+ 内容检查（大小写重复、路径长度、`.disabled`/`.old`、排除清单）+ 发布门禁（逐条目可读且哈希匹配）。

**测试**：`SEC-165` 断言恶意归档在创建内容对象或引用之前被拒绝，且内容库与数据库均无残留。

### THR-064 缓存指令导致静默停更

**威胁**：manifest 响应带 `max-age` 时，HMCL 在缓存期内完全不请求，运营者发布的更新对玩家不可见且服务端无感知（已运行验证，见 `HCB-018`）。

**应对**：manifest 端点的 `Cache-Control` 恒为 `no-cache`，且不设未来的 `Expires`。该端点有独立中间件管线，不受全局响应头配置影响。

**测试**：`SEC-280` 契约测试断言响应头；`SEC-281` 断言即使全局配置改变该端点也不变。

## 10. 节点安全

### THR-070 伪造 Agent 接入

**应对**：注册令牌一次性、有短有效期、只存哈希；注册成功后签发长期凭据，同样只存哈希；连接必须 TLS（回环例外）；协议版本协商。

**测试**：`SEC-290` 过期/重复/已作废令牌被拒；`SEC-291` 无效凭据被拒。

### THR-071 中间人

**应对**：Agent 默认信任系统证书存储；允许固定证书指纹用于自签场景。明文仅在双方同机且目标为回环时允许。

**测试**：`SEC-300` 非回环明文连接被拒；`SEC-301` 指纹不匹配时连接被拒。

### THR-072 凭据泄露后的持续访问

**应对**：凭据可轮换与吊销；吊销后立即断开且无法重连；轮换与吊销写入审计。

**测试**：`SEC-310` 吊销后连接被拒。

### THR-073 恶意控制平面指令

**威胁**：控制平面被攻破后向 Agent 下发越界指令（例如删除任意目录）。

**应对**：Agent 对每条指令独立校验，不信任控制平面传来的路径：
* 工作目录必须是该实例已登记的路径；
* 文件路径必须在工作目录内（完整校验链）；
* `DeleteWorkingDirectory` 只对 `OwnedByServitium = true` 的实例生效，且目标必须位于受管基路径之下、不是基路径本身；
* Java 导入解包受归档检查约束。

**测试**：`SEC-320` 构造越界指令，断言 Agent 拒绝。

## 11. 数据保护

### THR-080 秘密泄露到日志与导出

**应对**：统一的脱敏中间层，作用于日志、事件载荷、API 响应、错误消息与诊断导出。脱敏对象：密码与哈希、会话令牌、CSRF 令牌、API Key、节点凭据、注册令牌、Channel 令牌、RCON 密码、OIDC Client Secret、TLS 私钥与 PFX 密码、Windows 运行账户密码、TOTP 密钥与恢复码。

**测试**：`SEC-330` 在配置了全部秘密的环境中生成诊断导出并遍历日志，断言不含任何已知秘密值；该测试对每个秘密类型单独断言。

### THR-081 数据目录被非授权读取

**应对**：安装器设置 ACL：`SYSTEM`、`Administrators` 与服务账户完全控制，`Users` 无权限。敏感配置额外用 DPAPI（机器范围）加密。

**测试**：`SEC-340` 安装后校验 ACL（需要权限，见 `../development/workflow-development.md` 的权限阻塞流程）。

### THR-082 审计被篡改

**应对**：审计日志实体无更新与删除的应用层路径；架构测试断言数据访问层不对该表产生 UPDATE/DELETE；仅有一个按保留期执行的清理作业，该作业本身写审计条目。

**测试**：`SEC-350` 架构测试；`SEC-351` 尝试通过任何 API 修改审计条目均返回 `404`/`405`。

## 12. Desktop 中的 WebView2

### THR-090 WebView2 被用作攻击面

**应对**：
* 只加载本地打包资源（`ms-appx-web://` 或本地虚拟主机映射），禁止导航到任何其他来源（`NavigationStarting` 中拦截）；
* 禁用新窗口与弹窗；
* 不启用通用宿主对象注入，仅暴露一组白名单化的消息通道（终端输入输出、编辑器内容读写、主题变更）；
* WebView2 内不发起网络请求，所有数据由宿主经消息通道传入；
* 不共享 Cookie 或会话；
* 禁用开发者工具（Release 构建）。

**测试**：`SEC-360` 断言导航到外部 URL 被拦截；`SEC-361` 断言宿主对象未暴露。

## 13. 限流

| 端点组 | 默认策略 |
| --- | --- |
| 登录与 TOTP | 按用户名与 IP 双维度，指数退避 + IP 封禁 |
| API Key 认证 | 按 Key 每分钟 600 次 |
| 一般 REST | 按会话每分钟 1200 次 |
| 文件流 | 按会话并发数与节点级速率上限 |
| HMCL 端点 | 按 IP 每分钟 2000 次（须高于 64 并发 × 5 重试的峰值） |
| 本机换票管道 | 每进程每分钟 10 次 |

限流响应返回 `429` 与 `Retry-After`。
