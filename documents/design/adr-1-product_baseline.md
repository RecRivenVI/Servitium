# 产品固定决策

## 状态

已接受

## 背景

用户确认的产品依据；仓库治理与测试流程以根规范和项目规范为准。

## 决策

本文件记录 Servitium 已由用户明确确定的产品与技术决策。

**这些决策不可协商。** 后续任何阶段的编码 Agent 不得重新征询、不得自行改变、不得以「实现困难」为由绕过。确有必要变更时，按 `AGENTS.md` 的流程写入 `../project/backlog-product.md` 并等待用户裁决。

## 1. 决策清单

| 编号 | 主题 | 固定决策 |
| --- | --- | --- |
| DEC-01 | 节点范围 | Windows 分布式架构：中央控制平面、WinUI/Web 客户端和多个 Windows Agent |
| DEC-02 | 联网边界 | 剔除厂商与商业在线依赖，但保留自托管 Web、节点通信、HMCL 分发、URL 下载、私有源和可自托管 OIDC |
| DEC-03 | Web 技术 | React、TypeScript、Fluent UI React v9，由 ASP.NET Core 托管构建产物 |
| DEC-04 | 运行形态 | `Servitium.Server` 和 `Servitium.Agent` 以 Windows 服务常驻 |
| DEC-05 | 双端一致性 | Desktop 与 Web 的信息架构、字段、动作、状态、权限和文案一致；允许平台相关的响应式重排 |
| DEC-06 | 分支起点 | `develop` 是不继承旧产品代码的全新开发起点 |
| DEC-07 | 最终交付形态 | 完整安装包和远程 Agent 专用安装包，不提供 Portable |
| DEC-08 | 实例范围 | 仅管理 Minecraft Java 服务端 |
| DEC-09 | 工作目录 | 管理员可登记任意绝对工作目录；路径是实例属性，不是实例身份 |
| DEC-10 | HMCL 范围 | 完整的 Archive、校验、不可变 Release、原子 Channel 和客户端自动更新流水线 |
| DEC-11 | Desktop 登录 | 使用 Windows 身份和受 ACL 保护的本机通道换取短期会话 |
| DEC-12 | 实例删除 | 删除登记和删除目录分离；外部工作目录永不递归删除 |
| DEC-13 | 系统支持 | Desktop 支持 Windows 11 x64；Server 和 Agent 支持 Windows 11、Windows Server 2022/2025 x64 |
| DEC-14 | Java 启动 | 默认结构化向导，同时提供受限制的高级原始命令模式 |
| DEC-15 | 容量目标 | 8 个 Agent、64 个实例、20 个并发登录会话、8 个并发终端 |
| DEC-16 | Web 暴露 | 默认仅监听回环；非回环开放必须配置受信 TLS 或明确的可信反向代理模式 |
| DEC-17 | 首发语言 | `zh-Hans` 与 `en-US` |
| DEC-18 | 界面设计 | 使用 Fluent 2；MCSManager 只提供功能、信息架构和交互行为参考 |

## 2. 派生约束

下列约束由上表直接推导，同样不可协商。

| 编号 | 派生自 | 约束 |
| --- | --- | --- |
| DEC-D01 | DEC-01 | Agent 主动连接控制平面；Agent 不监听任何入站业务端口 |
| DEC-D02 | DEC-01、DEC-16 | 浏览器与 Desktop 不直连 Agent；终端与文件流一律经控制平面中转 |
| DEC-D03 | DEC-02 | 不接入 Modrinth、CurseForge、SpigotMC、Azul、厂商模板源或任何在线目录 |
| DEC-D04 | DEC-04 | 不提供 Portable 模式，不提供「双击 exe 运行」的产品形态 |
| DEC-D05 | DEC-04 | 控制平面停止时，Agent 上的实例与本地计划任务继续运行 |
| DEC-D06 | DEC-05 | 任何只在一端实现的业务能力都视为缺陷，除非该能力本身是平台原生特性（托盘、系统通知、单实例） |
| DEC-D07 | DEC-06 | 不编写旧数据迁移、不保留旧架构兼容层、不引用旧产品代码 |
| DEC-D08 | DEC-08 | 实例类型字段只有一个取值；不设计可扩展的实例类型体系 |
| DEC-D09 | DEC-09 | 实例身份是 `Guid`；工作目录可修改而不改变实例身份 |
| DEC-D10 | DEC-12 | 只有 `OwnedByServitium = true` 的实例才允许「删除工作目录」 |
| DEC-D11 | DEC-14 | 高级原始命令模式默认关闭，需管理员在系统设置中显式开启，且每次使用写入安全审计 |
| DEC-D12 | DEC-15 | 性能与压力测试以该容量为基准，不以更低规模通过验收 |
| DEC-D13 | DEC-18 | 不引入 Ant Design、Material、Bootstrap 或任何非 Fluent 的组件库 |

## 4. 变更流程

1. 发现需要变更基线的事实或约束；
2. 在 `../project/backlog-product.md` 中新建条目，写明：当前要求、遇到的问题、建议方案、影响范围（涉及哪些文档与阶段）；
3. 停止相关工作，继续推进不受影响的部分；
4. 等待用户裁决；
5. 用户批准后由用户或经用户明确授权的一轮任务修改本文件与受影响的受保护文档。

未经用户批准，任何人不得修改本文件。

## 后果

保留产品范围与安全不变量；不据此恢复已退役的机械门禁。
