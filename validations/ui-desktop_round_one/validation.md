# Desktop 首轮检查点场景验证

## 目标

验证用户 2026-10-21 授权的首轮 Desktop：依赖安全修复、导航与登录、实例工作区六标签、分类设置。两轮现已合并，但本定义只记录首轮检查点。Web、后续四类页面重写、真实 Minecraft/HMCL 样本和完整平台验收不属于本次通过声明；后者仍见[客户端完整场景](../ui-clients/validation.md)。

## 运行

1. 使用 global.json 指定的官方免安装 SDK，显式命令运行，不改系统环境；按[工作流](../../documents/development/workflow-development.md)锁定还原、Release 构建和运行全部现有测试。
2. 在仓库外启动自己构建的 Server、Agent 与合成 Java 夹具，独立目录、数据库和回环端口，记录自己创建的 PID；不得启动、停止或修改已有服务和用户真实数据。
3. 实际走初始化/登录/两步验证、导航与返回、连接管理；运行、停止、崩溃、离线、空、错误、无权限、未保存和长操作状态。普通账户只获得一组合成 grant。
4. 实际验证终端命令、文本保存和上传、配置与备份、模组切换、计划编辑与执行、实例配置和分类设置保存，并经现有 API 或自有夹具对照结果。
5. 对每个首轮页面、标签和设置分类，在应用自己的深浅色和窄宽窗口运行；只用代码截取本应用窗口，图片保存在仓库外并亲自查看，不使用 Computer-Use。
6. 对冻结候选完整还原、构建、测试、生成验证及依赖审计一次；记录实际命令与输出。自动验证不发送真实键鼠输入，不激活窗口；仅通过 UI Automation 控件模式操作，并核对自动化树的可聚焦属性、快捷键语义及 ViewModel/命令测试。测试窗口不激活显示，截图按句柄。已有按键证据保留，不再重跑。
7. 通过[一次人工清单](../../documents/usage/guide-desktop_acceptance.md)请求用户判断材质、动效与手感；运行细节与结果放仓库外，当前结论写进进度及技术债。

## 通过标准

- 与既有协议、授权及安全不变量一致，操作实际结果与界面反馈一致；未支持的原型能力明确列出，不能补示例数据或降低审计。
- 首轮页面不由 ContractPage 生成；旧第二轮页面仍可从新导航进入，权限撤回不保留旧数据。
- 深浅色、窄宽窗口均无阻断操作的遮挡；状态、空态与错误给出可理解的下一步；表单脏状态、校验和确认行为与实际保存一致。
- 新状态与校验回归、现有全部测试无失败和跳过；冻结构建无警告，生成无差异，审计无已知漏洞。
- 主要操作的键盘可达性按自动化树和命令层核对；真实 Tab 顺序与按键手感进入人工清单，自动化不发送输入。任何缺环境或只能由人判断的项目记录“无法比较”，不虚报。截图自查与用户验收分别记录，不互相替代。
